# LIORA OUTLOOK — 제품 방향과 구축 원칙

이 문서는 2026-09-21 사용자와 합의한 제품 방향을 기록한다. 기존 `00`~`08` 문서와
추진안은 이전 설계의 배경으로 보존한다. 제품 정체성, 개발 위치, 초기 구축 범위,
정형·비정형의 역할에 관해 충돌하면 이 문서의 최신 합의를 우선한다.
기존의 세부 모델·아키텍처를 모두 구현해야 한다는 뜻으로 이전 문서를 읽지 않는다.

## 1. 무엇을 만드는가

LIORA의 세 번째 프로젝트 **OUTLOOK**으로, 중장기 **Market Outlook**을 만든다.

| 프로젝트 | 제품의 흐름 |
|---|---|
| ASK | 묻고 말하기 |
| LISTEN | 듣고 파악하기 |
| OUTLOOK | 보고, 앞을 내다보기 |

OUTLOOK 아이콘은 기존 그래프에서 망원경(telescope) 방향으로 변경한다.
HH·JKM·WTI 등의 중장기 가격 추정과 함께 여러 시장의 수요·공급 전망을 다룬다.
수요량, 생산량, 공급능력, 교역량, 수급 차이는 각각 중요한 결과물이다.
가격 전망만으로 제품의 범위를 제한하지 않는다.

사용자가 답을 얻어야 할 질문은 다음과 같다.

- 앞으로 가격과 수급은 어떻게 전개될 수 있는가?
- 어떤 데이터와 가정 때문에 그렇게 보는가?
- 무엇이 달라지면 전망을 수정해야 하는가?
- 새 정보로 어느 가정이 바뀌었고, 결과가 얼마나 달라졌는가?

## 2. 개발 위치와 통합 방향

- 현재 OUTLOOK 분석·모델·화면 개발은 **scen_dev**에서 진행한다.
- **DB는 NGIP 중앙 DB 하나로 관리한다.** 공개 데이터 수집·검증·적재·정기 갱신은 NGIP job이 담당한다.
- scen_dev는 기존 `db.py`와 읽기 전용 계정으로 조회한다. 별도 수집 스케줄이나 운영용 데이터 사본을 만들지 않는다.
- 원천 API 응답은 NGIP의 S3에 감사·재현용으로 보존한다. OUTLOOK의 조회 기준은 중앙 DB다.
- 지금 NGIP 내 LISTEN에 OUTLOOK을 구현하지 않는다.
- 추후 LIORA 독립 시 통합하여 배포한다.
- LISTEN과 OUTLOOK의 기능적 연결은, 포착한 변화가 전망의 어느 가정을 흔드는지
  연결하는 것이다. 기능 연결 API와 LIORA 독립 시의 배포 구성은 후속 설계한다.

## 3. 기존 모델에서 계승할 철학

엑셀의 변수 선택·분석 기간·데이터 변환·계수·통계 지표와 Signpost 구조에는
“변수의 관계를 직접 탐색하고, 그 변수를 움직이는 요인까지 관찰한다”는 의도가 담겨 있다.
Kearney 보고서는 이를 관측, 미래 가정, 수급·시장 전망, 의사결정으로 연결한다.

기본 흐름은 다음과 같다.

**관찰할 지표와 근거 → 변수별 미래 가정 → 수급 전망 → 가격 전망 → 실제 변화와 비교하며 가정 수정**

과거 관계를 분석·검증하는 기능과 미래 가정을 만들고 비교하는 기능을 모두 중요하게 다룬다.
회귀분석은 사용 가능한 방법 중 하나다. valuation Python 모델을 연결했던 의도는
통계와 변수별 의미를 눈으로 확인하기 위함이며, 해당 모델의 구조를 그대로 제품의
중심으로 채택하기로 한 것은 아니다.

통계적 유의성, 예측 기여도, 시장에서의 인과적 중요성을 구분한다.
기존 자료의 계수·산식·점수는 재검증 대상이다. 상대적 발생 가능성 점수를 실제 확률로
그대로 해석하지 않는다.

**2026-09-22 엔진 개념 추가 합의:** 각 사인포스트를 잘 설명하는 개별 모델을 여러 단계로
연결한다. 한 모델의 출력이 다음 모델의 입력이 되고, 한 번의 실행으로 각 사인포스트의
미래 경로를 종합해 수급·가격 시나리오를 만든다. 통계모델의 비교·선택은 이 통합 구조를
뒷받침한다. 변수별 관계뿐 아니라 하위 추정을 상위 모델에 전달했을 때의 전체 결과도
검증한다. 구체적 연결도와 후보 모델은
[사인포스트 다단계 모델 엔진 설계](13-outlook-statistical-model-design.md)에 기록한다.

**동일 대화의 확률 구조 구체화:** 각 단계는 가능한 결과와 조건부 확률을 내놓고, 이전
단계에서 형성된 상황에 따라 다음 단계의 확률이 달라진다. 사용자가 든 정책·강달러·산유국
재정·OPEC 증감산 예시처럼, 서로 다른 반응이 이어지는 미래 경로와 그 가능성을 함께 다룬다.
확률의 데이터·전문가 판단 근거와 불확실성을 남기며, 새 정형·비정형 증거로 갱신한다.
동적 확률 네트워크와 경로 시뮬레이션은 이를 위한 설계 후보이며 아직 모델 채택은 아니다.

**모니터링 범위에 관한 추가 요구:** 미래 경로를 전개하면서 가능성이 매우 낮은 가지는
더 깊은 계산을 중단하고, 가능성이 높은 세계들을 선정해 모니터링 대상으로 제시한다.
개별 경로의 확률과 선정 세계들이 포괄하는 전체 확률을 구분하고 제외된 확률도 남긴다.
새 증거로 확률이 달라지면 중단했던 가지를 다시 평가한다. 구체적인 확률 임계값과
커버리지 목표는 아직 확정하지 않았다.

**가격 전망의 추가 요구:** 선정 세계마다 가격을 확률분포와 범위로 제시하고, 세계별
확률을 결합한 전체 전망도 보여준다. 같은 대상 시점의 과거 전망과 현재 전망을 비교해
가격 수준과 범위·변동성이 어떻게 달라졌는지 설명해야 한다. 가정 변화, 세계별 확률 변화,
모델 변경과 근거를 추적하며, 예측구간 확대와 실제 가격의 변동성 확대를 구분한다.

**화면 설계 요구:** 사용자는 화면 배치보다 먼저 할 일·기능·화면 간 구조를 정하기를
원한다. 참조 대화 `LIORA Frontend 화면 구상`에서는 LIORA가 시장을 관통하는 AXIS를
먼저 제안하고 사용자가 선택하며, 하위 요인·전달 경로·수급·가격·대비까지 연결하길 요청했다.
기능 구조 제안은 [사용자 업무·기능·화면 구조](14-outlook-functional-architecture.md)에 기록한다.
화면 수나 기존 시안의 탭 구성을 선행 제약으로 삼지 않는다.

사용자가 제안한 상위 화면 구분은 **Perspectives / Projections / What If Analysis**다.
Perspectives는 LIORA의 현재 세계관·AXIS·영향 관계, Projections는 연결된 가능한 세계와
가격·수급 전망·변화 근거·관찰 대상, What If Analysis는 대안 세계와 대응 선택·대비를 다룬다.
Projections의 요약과 연결 구조를 설명할 deep dive의 구체적 배치는 후속 결정으로 남긴다.

현재 구축 순서는 **Perspectives → Projections → What If Analysis**로 잡는다.
첫 단계는 근거를 가진 시장 해석·AXIS 제안·사인포스트와 영향 관계의 탐색을 우선한다.
What If의 연쇄 재계산과 값 고정 등 상세 동작은 이후 설계할 때 다룬다.

Perspectives는 1980년·1990년·2000년 등 과거 시점에서 어떤 AXIS를 선정하는지도
검증한다. 시대의 사후 설명과 당시 정보로 유용한 관찰 축을 정하는 능력을 구분하며,
선정 근거·영향 경로·관찰 신호·시점별 갱신을 평가한다. 당시 자료 가용성과 현대 LLM의
사후 지식 혼입 한계를 표시하고, 현재부터 저장한 관점의 후속 검증도 함께 설계한다.

## 4. 비정형은 전망을 계속 갱신하기 위한 핵심 기능

**사용자는 과거 프로젝트가 실패한 이유를 비정형 정보를 다루지 못했기 때문이라고 설명했다.**

이번 대화에서 확인한 문제는, Signpost와 영향 경로를 정의해도 변화가 시작됐다는
정보를 읽어 기존 모델의 가정에 연결하지 못하면 전망이 갱신되지 않는다는 것이다.
사람이 뉴스와 보고서를 읽고 해석한 뒤 엑셀 가정을 고쳐야 하는 연결부가 핵심 과제다.

예를 들어 액화설비 용량과 예정 준공일은 정형데이터로 관리할 수 있다. 그러나 미래
공급 가정을 재검토하게 만드는 정보는 실적발표의 표현 변화, 인허가 지연, EPC 협상 문제,
장기 구매계약 확보 지연, 사업자의 투자 우선순위 변경 같은 문장으로 먼저 나타날 수 있다.
이는 동작을 설명하기 위한 예시이며 특정 프로젝트에 대한 사실 판단은 아니다.

**비정형을 활용하는 목적은 우리가 세워둔 전망의 전제가 아직 유효한지 계속 확인하는 것이다.**
새로운 정보가 숫자 통계에 반영되기 전에도 미래 가정을 재검토할 근거를 확보해야 한다.
뉴스 요약·분류·검색에서 끝나지 않고 다음 흐름까지 연결한다.

**정보 발견 → 관련 시장·설비·변수 식별 → 기존 가정과의 충돌 확인 → 시나리오 반영 → 전망 변화 확인**

관측된 사실, 정보에 대한 해석, 모델에 반영한 가정을 구분한다. 근거와 불확실성을
함께 남겨 단일 기사나 AI 해석이 자동으로 확정 전망이 되지 않도록 한다.

## 5. “정형부터 시작”의 정확한 의미

scen_dev의 초기 구상이 너무 넓었다는 사용자의 판단에 따라, 정형데이터로 계산 가능한
전망의 뼈대를 먼저 검증하고 비정형 처리를 단계적으로 확장한다.

**구현은 정형부터 시작하되, 비정형 근거와 가정의 연결은 처음부터 설계에 포함한다.**
비정형을 완성된 모델에 나중에 붙이는 부가 기능으로 취급하지 않는다.

첫 구현에서 지향할 최소 흐름은 다음과 같다.

**실적 데이터 → 수요·공급의 기본 전망 → 가정별 조정 → 수급과 가격 결과 비교**

초기에는 사람이 기사·보고서의 근거를 붙여 가정을 조정하는 흐름으로 시작할 수 있다.
이후 수집·분류·변수 연결·가정 재검토 제안의 자동화를 확장한다.
이를 위해 가정에는 출처와 근거, 적용 대상, 적용 시점과 기간, 변경 내용과 이유,
연결된 시나리오를 추적할 수 있는 자리를 둔다. 구체적인 저장 형식은 후속 설계에서 정한다.

전체 Signpost 목록, 전사 경영체계, 고도화된 Regime·Transition·Semantic 모델을
첫 구현의 필수 선행조건으로 삼지 않는다. 하나의 시장에서 근거·가정·계산·결과가
끝까지 연결되는 흐름을 우선한다.

## 6. 초기 데이터 운용 결정

2026-09-22 다음 원칙을 추가로 확정했다.

- 미국 기상은 첫 모델에서 **NOAA 인구가중 HDD/CDD만** 사용한다. 기존 엑셀의 주별
  기온·평년편차·폭풍 계열은 초기 입력에서 제외하고, HDD/CDD의 설명력과 안정성이
  부족할 때 추가 기상변수를 검토한다.
- 국가별 가스 저장량은 먼저 JODI-Gas의 **월말 재고 `CLOSTLV`**를 사용한다.
  재고 증감 `STOCKCH`는 별도 변수이며 저장량을 대신하지 않는다. JODI가 저장 형태를
  LNG 탱크와 지하저장으로 나누지 않고 일부 국가가 보고하지 않는 한계는 그대로 표시한다.
- HH·JKM·TTF·WTI 등 가격계열의 세부 정의와 추가 연결은 후속 단계로 미룬다.
- LNG 운임은 기존 엑셀의 월간 글로벌 선형별 평균과 중앙 DB의 일별 지역별 단기
  용선료·항로비가 서로 다른 계열임을 전제로 한다. 두 자료를 한 시계열로 바로 잇지 않는다.
- 미국 외 액화능력은 현재 운영능력, 건설 중·FID 프로젝트, 예상 준공일을 구분한다.
  공개 자산 목록으로 현재 스냅샷을 만드는 것과 과거 시점별 능력을 재구성하는 일을
  별도 난이도로 본다.

세부 데이터 정의와 실제 커버리지는
[엑셀 기준 데이터 확보 범위와 DB 공백](10-outlook-data-coverage.md)에 기록한다.

## 7. 아직 정하지 않은 것

- **데이터 최소 범위 추가 합의(2026-09-21):** 기존 엑셀 두 개에 있던 데이터를 최소 확보
  기준으로 삼는다. 미국 중심 DB를 재사용하되 유럽·아시아·기타 생산국의 수급으로 확장한다.
  데이터 확보 범위와 첫 모델에 실제 투입할 변수는 구분한다.
  현황과 공백은 [엑셀 기준 데이터 확보 범위와 DB 공백](10-outlook-data-coverage.md)을 참고한다.

- 첫 대상으로 삼을 시장과 HH·JKM·WTI의 구현 순서
- 전망 기간, 월·분기·연 단위와 지역·부문별 상세 수준
- 미국 외 액화능력 원천의 무인 다운로드 방식과 갱신 주기
- 수급·가격 추정 방법과 변수별 검증 기준
- 비정형 자동화 범위, 사람의 검토 지점과 화면 구성
- 기존 scen_dev 및 valuation_model_23 코드의 재사용·축소 범위

이 문서를 근거로 기존 구현을 일괄 삭제하거나, 위 선택 사항이 확정됐다고 간주하지 않는다.
다음 설계에서는 최신 방향에 맞춰 기존 자산을 검토하고 최소 범위를 구체화한다.
