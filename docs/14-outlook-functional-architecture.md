# LIORA OUTLOOK — 사용자 업무·기능·화면 구조

## 1. 이번 설계의 범위

사용자가 수행할 업무, 필요한 기능, 기능을 담을 논리적 화면과 연결을 정의한다.
색상·카드·차트 배치·와이어프레임은 이 문서의 범위가 아니다. 아래의 화면은 기능의
책임 단위이며 반드시 각각 독립된 페이지나 동등한 최상위 탭이어야 한다는 뜻은 아니다.

[제품 방향](09-outlook-direction.md)과 [다단계 확률 모델 설계](13-outlook-statistical-model-design.md)를
바탕으로 한다. 참조 대화 **LIORA Frontend 화면 구상**의 사용자 요구도 직접 확인했다.

- LIORA가 먼저 시대와 시장을 관통하는 AXIS를 제안한다.
- 사용자가 환경·전쟁·금융 등 관심 축을 선택할 수 있어야 한다. 2~10개는 사용자의
  구상 범위이며 고정된 축 수나 서로 독립적인 시나리오 차원의 수로 확정하지 않는다.
- 축을 움직이는 요인과 전달 경로, 수급·가격 영향, 세상에 대한 설명과 대비를 연결한다.
- 해당 대화에서 사용자는 UI상 위치를 `LIORA > LISTEN > OUTLOOK`으로 표현했다.
  이 문서는 그 위치를 탐색 맥락으로 사용한다. 개발은 scen_dev, 중앙 DB는 읽기 전용으로
  사용한다는 현재 경계를 바꾸지 않는다.
- 참조 대화에서 요청한 shared/design-system 활용은 후속 시각 설계 때 실제 상태를 확인한다.
  이전 HTML 시안의 화면 수·메뉴·대비 옵션은 확정 요구로 승계하지 않는다.

## 2. 사용자가 이 제품에서 끝낼 일

1. **관점 정하기:** 어떤 시장과 기간을 보며, 지금 어떤 축이 중요하고 왜 중요한지 선택한다.
2. **관계 이해하기:** 어떤 신호가 어떤 경로·조건·시차로 결과에 영향을 주는지 확인한다.
3. **가능한 미래 읽기:** 유력한 세계들과 그 확률·수급·가격 범위를 비교한다.
4. **판단 바꾸기:** 새 증거가 어느 가정과 확률을 바꾸고 과거 전망을 왜 수정했는지 확인한다.
5. **가정 시험하기:** 궁금한 조건을 바꿔 어떤 세계와 결과가 달라지는지 계산한다.
6. **미래 준비하기:** 무엇을 관찰하고 언제 어떤 준비를 검토할지 기록한다.

같은 사용자가 전망을 읽기도 하고 모델·가정을 검토하기도 한다. 첫 화면에서 모든
통계 설정을 요구하거나, 모든 기능을 한 개의 요약 화면에 집어넣지 않는다.

처음 들어왔을 때는 LIORA가 시장·관심 기간에 맞는 축 후보와 이유를 제안한다.
이미 관점이 만들어져 있다면 마지막 판단 이후 달라진 것과 현재 유력한 세계가 첫 진입점이다.
가격, 사건, 특정 사인포스트에서도 관련 관점으로 바로 진입할 수 있어야 한다.

## 3. 화면 간 공유하는 대상과 의미

| 대상 | 의미 | 예시 및 주의점 |
|---|---|---|
| 관점 | 시장·기간·관심 축과 기준 전망을 함께 보는 작업 맥락 | 미국 가스의 향후 3년 전망. 가격 상품의 정의는 별도로 고정 |
| AXIS | 시장 변화를 이해하기 위한 상위 주제·동인 | 금융 여건, 지정학, 에너지 전환. 필요하면 여러 하위 축으로 분해 |
| 사인포스트 | 관찰하거나 추정하는 구체적 상태·변수·사건 | 달러지수, 재정 상태, 증감산 결정, 프로젝트 준공일 |
| 관계 | 변수 사이에 제안되거나 검증된 연결 | 입력·출력·방향·시차·조건·근거·불확실성을 보유 |
| 모델 | 여러 입력으로 한 대상 또는 여러 대상을 추정하는 방법 | 회귀·행동 확률·회계식. 화살표 하나마다 독립 모델을 강제하지 않음 |
| 세계 | 조건들이 연결된 미래 경로 또는 유사 경로의 묶음 | 특정 정책·수요·공급 전개가 함께 나타나는 미래 |
| 전망 실행 | 특정 정보·가정·모델 버전으로 계산한 결과 | 세계 확률, 수급과 가격 분포, 커버리지 및 계산 상태 |
| 증거 | 관측값·문서·기사·발표 등 판단 근거 | 원문 사실, 해석, 실제 반영한 가정을 구분 |
| 관찰 조건 | 판단을 다시 볼 필요가 생기는 신호와 기준 | 발표, 임계점, 지속기간, 상충 증거의 등장 |
| 대비 항목 | 특정 미래에 대비해 검토하거나 준비할 선택 | 필요 조건, 준비 시간, 근거, 재검토 시점 |

AXIS를 숨기는 것은 관찰 화면의 관심 범위를 바꾸는 일이다. 그 축의 영향을 기준
모델에서 제거하는 행동과 구분한다. 후자는 가정실험으로 명시해 결과를 비교한다.
AXIS가 반드시 하나의 점수일 필요는 없다. 점수를 쓰면 구성 지표와 산정 근거를 제공한다.

## 4. 상위 3화면과 내부 기능

사용자는 앞서 나눈 업무 기능을 다음 세 화면으로 묶자고 제안했다. 이 구분을 이후
화면 설계의 큰 틀로 삼는다. U1~U9는 각 화면 안의 업무 기능 식별자로 유지한다.

| 상위 화면 | 핵심 질문 | 포함 기능 | 주요 산출물 |
|---|---|---|---|
| **Perspectives** | 지금 LIORA는 세상을 어떻게 이해하는가? | U1 시장 관점, U2 핵심 축, U3 영향 관계 | 현재 세계관, 중요한 AXIS, 작동 조건과 가능한 영향 경로 |
| **Projections** | 그 관점과 조건들이 결합하면 어떤 미래가 가능한가? | U4 가능한 세계, U5 가격·수급 전망, U6 변화와 근거, U7 관찰 대상 | 확률을 가진 미래 세계, 가격·수급 분포, 변경 이유와 다음 관찰 신호 |
| **What If Analysis** | 이런 세계가 오거나 우리가 다르게 대응하면 어떻게 되는가? | U8 가정실험, U9 우리의 대비 | 대안 세계와 대응 선택의 비교, 사업 영향, 준비·재검토 조건 |

Perspectives는 관련 근거와 함께 LIORA의 해석을 제시하고, 사용자가 축과 관점을
검토할 수 있게 한다. Projections는 그 관점 아래 변수의 조건부 관계를 따라 가능한
세계를 구성한다. AXIS를 서로 독립적인 선택지로 간주해 모든 조합의 확률을 단순 곱하지 않는다.
What If Analysis는 Projections의 세계 또는 기준 전망을 가져와 조건과 대응을 바꿔 시험한다.
실험 결과는 저장해 비교하며 기준 관점에 반영할 때 그 변경을 명시한다.

### 4.1 Projections의 요약과 deep dive

변화·근거·연결 구조를 한 화면에 모두 펼칠지 별도 상세 화면으로 보여줄지는 사용자가
열린 결정으로 남겼다. 현재 추천안은 **본 화면의 필수 요약 + 선택한 결과에서 시작하는 상세 탐색**이다.

- 본 화면에는 가능한 세계와 확률, 가격·수급 범위, 중요한 변화, 다음 관찰 신호를 둔다.
- 세계·확률·가격 범위의 변화를 선택하면 해당 계산의 상세로 들어간다.
- 상세는 '무엇이 변했나 → 어떤 가정·확률이 바뀌었나 → 어느 관계로 전달됐나 →
  어떤 자료·문서가 근거인가'를 연결한다. Perspectives의 변수·관계 상세를 재사용한다.
- 들어갈 때와 돌아올 때 시장·대상 기간·기준일·선택 세계·비교 실행을 유지한다.
- deep dive는 네 번째 상위 제품 영역으로 늘리지 않는다. 옆 패널·하위 탭·별도 상세 페이지
  중 어떤 방식이 적합한지는 후속 화면 배치에서 정한다.

### 4.2 What If Analysis의 두 실험 축

1. **대안 세계:** 외부 조건을 바꾸면 어떤 수급·가격 경로가 되는가? 낮은 확률로
   잘라냈던 세계도 의도적인 스트레스 실험 대상으로 가져올 수 있다.
2. **대응 대안:** 같은 세계에서 우리가 서로 다른 선택을 하면 사업 영향이 어떻게 달라지는가?
   여러 세계에 걸쳐 공통으로 유효한 준비와 특정 세계에서만 유리한 선택을 비교한다.

대안 세계 × 대응 선택의 비교를 지원하되 사용자 사업의 노출·비용·제약이 있어야
수치 영향을 계산할 수 있다. 자료가 없으면 필요한 정보와 정성적 준비 항목을 제시한다.
우리의 대응이 시장 가격 자체를 바꾼다고 자동 가정하지 않는다. 시장 영향까지 계산하려면
그 연결을 설명하는 별도 모델이 필요하다. 강제로 만든 대안 세계와 기준 모델이 산출한
발생확률을 구분한다.

### 4.3 내부 업무 기능과 지원 기능 목록

아래 9개 업무 기능을 세 상위 화면에 배치하고, 데이터 상태·모델 검증은 공통 지원
화면으로 제공한다. 지원 기능은 관계·결과의 상세에서 접근할 수 있다.

| ID | 화면 | 사용자의 질문 | 사용자가 끝내는 행동 | 다음 연결 |
|---|---|---|---|---|
| U1 | 시장 관점 | 지금 무엇이 중요하고 지난번과 무엇이 달라졌나? | 현재 판단과 확인할 항목을 파악 | 축·세계·전망·변화·관찰 |
| U2 | 핵심 축 | 어떤 AXIS를 봐야 하며 왜 중요한가? | LIORA 제안을 검토하고 관심 축을 선택 | 영향 관계·관련 세계 |
| U3 | 영향 관계 | 이것이 무엇을 통해 수급·가격으로 이어지나? | 연결의 조건과 근거를 확인하고 관찰 대상을 선택 | 변수 상세·근거·모델·가정실험 |
| U4 | 가능한 세계 | 어떤 미래들이 얼마나 유력한가? | 세계를 비교하고 모니터링 범위를 정함 | 해당 세계 전망·분기 조건·대비 |
| U5 | 가격·수급 전망 | 어느 기간에 어느 범위까지 갈 수 있나? | 세계별·전체 분포와 위험을 비교 | 변화 설명·영향 관계·대비 |
| U6 | 변화와 근거 | 왜 판단과 범위가 달라졌나? | 과거·현재 차이와 원문 근거를 추적 | 관련 축·가정실험·재계산 결과 |
| U7 | 관찰 대상 | 다음에 무엇을 보면 판단을 바꿔야 하나? | 관찰 조건과 우선순위를 등록·관리 | 증거·세계 확률 변화·대비 |
| U8 | 가정실험 | 이 조건이 달라지면 어떤 미래가 되나? | 기준 전망을 복제해 가정을 바꾸고 결과를 비교 | 실험 세계·전망·저장된 비교 |
| U9 | 우리의 대비 | 이 미래에서 우리는 무엇을 준비해야 하나? | 사업 영향과 대응 조건을 검토·기록 | 관찰 조건·세계·판단 기록 |
| S1 | 데이터 상태 | 이 판단의 입력은 충분하고 최신인가? | 정의·갱신·결측과 영향을 확인 | 관련 변수·모델·영향받은 전망 |
| S2 | 모델 검증 | 이 관계와 확률을 얼마나 믿을 수 있나? | 후보·진단·단계별/전체 성능을 비교 | 관계 상세·실험·모델 버전 |

## 5. 내부 기능별 명세

### U1. 시장 관점 — 매일 돌아오는 출발점

- 현재 시장을 해석한 짧은 서술, 중요한 축, 유력한 세계, 가격·수급 범위, 다음 관찰 항목.
- 마지막 방문 또는 저장된 판단 시점 이후, 결과를 실질적으로 바꾼 변화와 연결 근거.
- 아직 반영되지 않은 새 정보와 반영 완료된 정보, 계산 중 결과와 완료 결과를 구분.
- 요약의 각 주장·숫자에서 같은 실행의 상세와 근거로 이동. 별도 숫자를 재작성하지 않음.
- 사용자는 변화 하나를 열거나 세계를 비교하거나 질문을 시작할 수 있다.
- 처음 사용해 기준 전망이 없으면 시장·기간 선택과 축 제안으로 안내한다. 데이터가 없으면
  가능한 구조와 계산되지 않은 항목을 보여주며 실제 전망을 흉내 내지 않는다.

### U2. 핵심 축 — 무엇을 중심으로 세상을 볼 것인가

- LIORA의 축 후보, 제안 이유, 관련 시장, 최근 변화, 연결된 사인포스트와 판단 근거.
- 중요도를 하나의 불투명한 점수로만 표시하지 않고 시장 영향·불확실성·관찰 가능성·
  다른 축과의 중복 등을 설명한다. 실제 계산되지 않은 중요도는 제안으로 표시한다.
- 관심 축 선택·추가·이름 수정·묶기·보류, 이전 선택과의 비교.
- 축의 상태와 변화 요인을 확인하고 U3의 구체적인 변수와 관계로 내려간다.
- 여러 축이 같은 변수를 공유할 수 있으며 중복 효과를 더하지 않는다.
- 산출물은 관심 축과 선택 이유를 기록한 관점이다. 축을 선택했다는 이유만으로
  확률이나 인과성이 검증됐다고 표시하지 않는다.

### U3. 영향 관계 — 무엇이 무엇을 움직이는가

- 선택한 축·사건·변수에서 수급·가격까지의 경로와 공통 원인, 피드백·시차를 탐색.
- 관계 선택 시 방향·영향 크기·작동 조건·시차·사용 모델·자료·근거의 강도를 확인.
- 상관관계, 예측에 도움이 되는 관계, 인과 가정을 둔 관계, 검증 전 가설을 구분한다.
  굵은 선이나 '높은 유의성' 배지만으로 인과가 증명된 것처럼 보여주지 않는다.
- 사인포스트 상세에서 과거 관측·미래 경로·불확실성·관련 증거·관찰 조건을 확인.
- 경로 간 비교, 조건·시차별 관계 변화 확인, 관찰 대상 등록, 가정실험 시작.
- 관계 변경은 근거와 버전을 가진 초안으로 다루며 계산 결과와 영향을 확인할 수 있다.

### U4. 가능한 세계 — 어떤 미래를 모니터링할 것인가

- 세계별 서술, 확률과 추정 불확실성, 주요 가정, 가격·수급 요약, 이전 대비 확률 변화.
- 어느 조건에서 갈라졌는지, 부모 조건과 분기 확률·누적확률을 단계별로 확인.
- 선정 세계의 전체 확률 커버리지, 제외 경로, 아직 계산하지 못한 경로를 구분.
- 중단한 가지의 이유와 재활성화 신호, 영향이 큰 위험 경로를 확인.
- 세계들을 나란히 비교하고 공통점·차이·이를 구분할 사인포스트를 확인한다.
- 특정 세계만 화면에서 선택하는 필터와 확률모형에서 제외하는 설정을 구분한다.
- 대표 세계 수를 반드시 셋으로 고정하거나 Base/Upside/Downside 명칭을 강제하지 않는다.
  서로 다른 세계가 유사한 가격을 만들 수 있으므로 가격만으로 세계를 구분하지 않는다.

### U5. 가격·수급 전망 — 각 세계에서 어떤 결과가 나오는가

- 가격, 수요, 생산, 교역, 재고, 설비능력·가동률을 대상별로 탐색. 중간 결과도 독립 산출물.
- 전체 분포와 선택한 세계 안의 조건부 분포, 중앙값·예측구간·상하방 위험을 비교.
- 월·분기·연간 집계와 현물/계약 등 대상 정의를 명시하며 비교 가능한 계열만 결합.
- 같은 대상 기간의 과거·현재 전망, 동일 예측시계의 성능 비교를 별도 모드로 제공.
- 가격 수준, 예측 범위, 세계 내부/세계 사이 불확실성, 실제·예상 변동성을 구분.
- 차이가 생긴 기간·항목을 선택하면 U6의 변화 설명과 U3의 영향 경로로 이동.
- 제외된 가지 때문에 전체 구간을 계산할 수 없으면 조건부 구간과 한계를 표시한다.

### U6. 변화와 근거 — 왜 판단을 바꿨는가

- 변경 이력: 관측 실적, 정책·기사, 가정, 세계 확률, 데이터 개정, 모델 변경을 구분.
- 동일 대상의 이전 실행과 현재 실행을 비교하고 수준·범위·확률 변화의 기여를 확인.
- 증거에서 원문·출처·발표 시점·관련 국가/설비/변수·해석·반영한 가정까지 추적.
- 반대 증거와 미해결 해석, 같은 발표를 재인용한 자료를 함께 확인한다.
- 새 증거를 관련 변수에 연결하거나 반영 후보로 보류하고, 실험에서 영향부터 확인.
- 기여도를 계산하지 못했다면 가능성 있는 설명임을 표시한다. 계산 결과 없는 수치 기여를
  문장 생성으로 채우지 않는다.
- LISTEN의 원문·검색을 재사용하는 접점이다. OUTLOOK은 전망과 연결된 근거를 중심으로 본다.

### U7. 관찰 대상 — 다음에 무엇을 봐야 하는가

- LIORA가 제안한 관찰 대상과 사용자가 추가한 항목, 관련 세계·대비 항목을 함께 관리.
- 선정 이유: 세계를 구분하는 힘, 결과에 미치는 영향, 결과보다 먼저 관측되는지,
  다음 발표·정책 결정 시점 등. 검증되지 않은 선행성은 가설로 표시한다.
- 수치 임계점뿐 아니라 사건 발생·지속기간·추세 전환·상충 증거를 관찰 조건으로 설정.
- 상태: 대기, 새 정보 도착, 기준 충족, 재평가 필요, 반영 완료. 기준 충족이 자동으로
  세계 확정이나 특정 사업 행동을 뜻하지 않도록 연결된 판단 단계를 표시한다.
- 저확률 가지의 복귀를 감지할 상위 신호도 보존한다.
- 산출물은 '무엇을 언제 왜 보고, 무엇이 달라지면 어느 판단을 다시 보는가'가 담긴 목록.
  실제 알림 채널·주기와 수집 자동화는 후속 기능으로 설계한다.

### U8. 가정실험 — 내가 궁금한 조건을 바꿔본다

- 특정 기준 전망을 복제하고 정책·기상·경제·준공·가동률·행동 가정 등을 변경.
- 관측 증거로 확률을 갱신하는 실험, 조건을 고정하는 실험, 정책 개입을 가정하는 실험을
  구분하고 계산 가능한 범위를 보여준다. 인과 조건이 없는 관계에 개입 효과를 보장하지 않음.
- 원래 확률과 강제로 선택한 조건을 구분한다. 실험자가 만든 세계에 발생확률을 자동 부여하지 않음.
- 변경한 입력, 영향받는 관계와 모델, 계산하지 못하는 항목을 실행 전에 확인.
- 실행 후 기준 대비 세계 확률·수급·가격 분포와 변화 경로를 비교.
- 실험 저장·이름 지정·비교·초기화. 기본 관점에 반영하는 행동은 명시적으로 구분한다.
- 숫자 조정의 의미를 이해할 수 있도록 단위·가능 범위·근거를 제공한다.

### U9. 우리의 대비 — 전망을 준비할 판단으로 연결

- 관심 사업·지역·기간과 구매/판매 등 노출 방향, 준비 기간, 제약을 입력할 수 있다.
- 세계별 사업 영향, 검토할 선택, 필요한 정보, 준비 시점과 재검토 조건을 연결.
- 사용자 사업 정보가 없으면 시장 차원의 영향과 확인할 질문을 제시한다. 일반적 시나리오만으로
  특정 회사에 유리한 행동이나 손익 금액을 임의로 확정하지 않는다.
- 여러 세계에서 공통으로 유효한 준비와 특정 조건에서만 유효한 준비를 구분.
- 대비 항목을 관찰 조건과 연결하고 근거·판단 시점·상태를 저장.
- 근거가 포함된 전망·대비 메모를 만들 수 있다. 수익·비용 계산은 해당 노출과 산식이
  확보된 항목에서만 제공한다.

### S1. 데이터 상태 — 어떤 입력을 사용할 수 있는가

- 중앙 DB의 계열 정의·단위·지역·기간·원천·최신 발표/관측 시점·갱신 상태.
- 결측·품질·개정 이력·시점 재현 가능 여부와 영향을 받는 사인포스트·모델을 확인.
- 원천 실적, 기관 전망, 사용자의 가정이 어디에 쓰였는지 구분.
- 데이터가 부족한 모델과 필요한 보완 항목을 확인. NGIP job 상태로 연결할 접점을 둔다.
- 운영 DB 읽기 전용 원칙을 유지한다. 이 화면을 신규 수집·배포 승인으로 해석하지 않는다.

### S2. 모델 검증 — 관계와 확률의 품질을 확인한다

- 대상 사인포스트와 입력 변수·변환·시차·학습 기간, 후보 모델과 선택 근거.
- 계수·관계의 방향과 안정성, 적용 가능한 유의성 지표, 예측 기여와 진단.
- 같은 시점·기간의 비교 기준, 단계별 성능과 앞 단계 예측값을 전달한 전체 성능.
- 확률 보정·구간 포함률·국면별 성능, 전문가 사전 가정과 민감도.
- 모델 없음, 데이터 부족, 실험 중, 검증됨, 재검토 필요 등 상태와 적용 한계를 표시.
- 후보를 시험하고 비교 결과를 저장하며 모델 버전을 명시적으로 선택할 수 있다.
  사용자에게 항상 최종 모델 하나를 선택하도록 강제하지 않는다.

## 6. 모든 화면에 공통으로 적용할 기능

### 맥락을 유지하는 이동

시장·지역, 전망 대상 기간과 집계 단위, 정보 기준일, 전망 실행/모델 버전,
전체/선택 세계, 기본 전망/내 실험을 공유한다. 여러 시장에 걸친 관계는 범위를 표시한다.
시장을 바꿨을 때 호환되지 않는 필터는 조용히 적용하지 말고 변경 사실을 알려준다.

전망의 숫자·문장·증거를 선택하면 동일한 기준일과 실행을 유지한 채 상세로 이동한다.
특정 과거 전망을 보고 있는데 근거 화면만 최신 자료로 바뀌는 일이 없어야 한다.

### 설명과 질문

각 화면에서 현재 보고 있는 세계·변수·기간을 맥락으로 ASK에 질문할 수 있다.
예: '이 세계의 확률은 왜 올랐나?', '이 연결의 반대 근거는?', '무엇이 바뀌면 이 전망을 버려야 하나?'
응답은 결과·모델·근거 상세로 연결하며 실제 계산과 해석을 구분한다.
질문으로 가정을 바꾸는 경우 변경안과 결과를 식별 가능한 실험으로 남긴다.

### 저장과 비교

관점, 실행 결과, 실험, 판단 메모를 저장하고 비교할 수 있다. 저장된 과거 결과는
새 정보로 덮어쓰지 않는다. 보고서·브리프에는 기준일·대상·확률 범위·핵심 근거를 포함한다.
외부 공유·게시 방식은 후속 설계 대상이며 현재 작업에서 발송하지 않는다.

### 계산되지 않은 상태도 설명

자료 부족, 지원되지 않는 관계, 추정 불가, 계산 중, 오래된 결과, 부분 계산을 구분한다.
전체 전망이 불가능해도 확인 가능한 구조·실적·근거·일부 사인포스트 결과는 보여준다.
실제 결과가 없는 예시는 예시로 표시하며 0·동일 확률·그럴듯한 범위로 대체하지 않는다.

## 7. 주요 사용자 흐름

### A. 처음 관점을 만든다

시장·관심 기간 선택 → LIORA의 축 후보와 근거 검토(U2) → 영향 경로 확인(U3) →
계산 가능한 세계와 전망 확인(U4/U5) → 기준 관점 저장 → 관찰 대상 선정(U7).
자료·모델이 부족하면 해당 공백을 남긴 구조 초안으로 저장할 수 있다.

### B. 매일 달라진 것을 판단한다

시장 관점(U1) → 중요한 변화 선택(U6) → 관련 증거·가정 확인 → 달라진 세계 확률(U4)과
가격·수급 범위(U5) 확인 → 관찰 조건 또는 대비 항목 수정(U7/U9).

### C. 가격 범위가 왜 달라졌는지 설명한다

동일 대상의 과거·현재 구간 선택(U5) → 세계 내부/세계 확률/모형 변경 기여 확인(U6) →
원인 후보 경로(U3) → 원문·실적·계산 근거 → 설명과 한계를 포함한 판단 메모 저장.

### D. 뉴스가 미래를 바꾸는지 시험한다

LISTEN 또는 변화 화면의 증거(U6) → 연결된 사인포스트(U3) → 해석·변경할 가정 검토 →
기준 전망을 복제한 실험(U8) → 세계와 결과 비교(U4/U5) → 반영/보류 사유 기록 → 관찰 조건(U7).

### E. 의사결정을 준비한다

관심 세계(U4) → 사업 노출과 영향(U9) → 대비 선택과 필요한 준비 기간 → 세계를 구분하는
신호(U7) → 재검토할 조건 등록 → 이후 변화가 생기면 해당 판단으로 복귀.

## 8. 메뉴와 탭을 정할 때의 원칙

- 상위 구분은 **Perspectives / Projections / What If Analysis**로 한다.
  아래 기능 명세를 다시 9개의 동등한 최상위 탭으로 분리하지 않는다.
- 자주 읽는 화면과 구조·가정을 편집하는 화면을 구분하되 같은 관점과 객체를 공유한다.
- U1은 요약과 진입점, U2/U3은 축과 관계의 원본, U4는 세계 확률의 원본,
  U5는 정량 결과의 원본, U6는 변화 설명·근거의 원본으로 책임을 나눈다.
- U7의 관찰 조건은 다른 화면에서도 등록할 수 있지만 관리 목록은 하나로 둔다.
- U8은 어떤 변수·세계에서든 시작할 수 있는 공통 실험 기능이며 저장한 실험 목록도 갖는다.
- U9는 세계와 관찰 조건을 사업 판단에 연결한다. 독립적인 일반 전략 생성 화면으로 만들지 않는다.
- 변수·관계·증거 상세는 여러 화면에서 같은 상세를 열도록 설계해 중복 기능을 줄인다.
- S1/S2는 깊은 검토가 필요할 때 들어가되 데이터·모델 한계는 주요 결과에서도 보인다.
- 각 상위 화면 안에서는 업무에 맞는 하위 탭과 상세 탐색을 둘 수 있다. 기능을 억지로
  한 화면에 압축하지 않으며, 요약에서 필요한 상세까지 이어지는 흐름을 우선한다.

### 8.1 단계별 구축 방향

**2026-09-23 후속 합의:** 화면 확장보다 AXIS 발견·선정·시대별 갱신 절차를 먼저 검토한다.
미국 에너지 전반을 중심으로 글로벌 연결을 다루며, 기존 미국 가스 화면의 여섯 후보는
선정 결과나 고정 기준이 아니다. 최신 범위와 첫 사례는
[AXIS 발견·선정·갱신 설계](16-axis-discovery-design.md)를 따른다.

사용자는 Perspectives → Projections → What If Analysis 순서로 난이도가 높아진다고
보고 Perspectives부터 진행하자고 제안했다. 이 순서를 현재 구축 방향으로 삼는다.
세 화면의 세부 기능을 모두 먼저 설계하기보다 각 단계의 역할과 다음 단계에 넘길 결과를 정한다.

| 단계 | 먼저 완성할 사용자 경험 | 다음 단계에 넘길 기반 |
|---|---|---|
| 1. Perspectives | LIORA가 현재 시장을 읽고 중요한 AXIS와 이유를 제안하며, 하위 사인포스트·현재 상태·영향 관계·근거를 탐색 | 근거와 상태가 연결된 시장 관점 및 변수 관계 구조 |
| 2. Projections | 위 구조에서 가능한 세계와 확률, 가격·수급 범위 및 변화 이유를 확인 | 기준 전망과 비교 가능한 미래 경로 |
| 3. What If Analysis | 조건과 대응 선택을 바꾸며 연결된 대안 세계를 탐색 | 준비할 대안과 판단 조건 |

첫 단계의 완료 기준은 사용자가 **'지금 중요한 축은 무엇이고, 왜 중요하며, 무엇을 통해
시장에 영향을 줄 수 있고, 다음에 무엇을 관찰해야 하는가'**를 근거와 함께 이해하는 것이다.
현재 실적·자료의 해석과 미래 관계의 가설, 통계적으로 검증한 관계의 상태를 구분한다.
Perspectives의 설명 품질과 관계 검증도 중요한 과제이며 단순 뉴스 주제 분류로 대체하지 않는다.

Projections의 정량 결과가 준비되기 전에는 U1의 세계 확률·미래 가격 범위 요약도 결과가
있는 것으로 전제하지 않는다. 사인포스트의 관찰 필요성은 첫 단계에서 설명할 수 있으며,
확률에 따른 모니터링 우선순위와 상세 관리 기능은 다음 단계에서 확장한다.

What If의 연쇄 재계산·추가 수정·값 고정과 낮은 확률의 세계를 계속 탐색하는 동작은
사용자가 나중의 상세 설계로 미루자고 했다. 현재는 역할만 보존하고 해당 동작의 상세
배선을 확정하지 않는다. 다음 설계 작업은 Perspectives 안에서 사용자가 읽고 선택하고
확인할 흐름을 구체화하는 것이다.

### 8.2 Perspectives의 시대별 AXIS 선정 검증

사용자는 1980년·1990년·2000년 등 과거를 기준으로 어떤 AXIS를 선정하는지 검증할
필요가 있다고 제안했다. 이를 Perspectives의 검증 요구에 포함한다. 당시의 중요한 축과
영향 경로를 포착하고, 시대와 정보가 달라지면 그 중요도를 적절히 갱신하는지 확인한다.
시대마다 반드시 다른 이름의 축을 내놓아야 한다는 뜻은 아니다.

**검증의 두 층을 구분한다.** 과거 시대의 자료와 시장 구조를 타당하게 설명하는 능력과,
그 시점에서 이후를 준비할 유용한 축·신호를 선정하는 능력은 별도로 평가한다.
이후 발생한 사건을 잘 설명했다는 사실만으로 당시 미래를 준비하는 데 유용했다고 판단하지 않는다.

각 시험에서는 정확한 기준일·대상 시장·관찰할 후속 기간을 정하고 당시 발표된 자료와
정형 통계의 당시 버전을 구성한다. 이후의 회고문, 사후 개정값, 알려진 사건의 결말은
선정 입력에서 제외한다. 당시 존재하지 않은 상품·지표를 현재 기준으로 소급 적용하지 않는다.
오래된 원문·통계 버전의 가용성은 아직 확인하지 않았으며, 재현할 수 없는 부분을 표시한다.

시험의 기본 흐름은 **과거 기준일 선택 → 당시 자료 제시 → AXIS·중요도·선정 이유·
영향 경로·관찰 신호 저장 → 다음 시점 자료와 결과 공개 → 유지·수정·누락·오경보 평가**다.
1980·1990·2000은 출발 사례로 삼되 유명한 변곡점만 고르지 않고 평상기와 시대 내부의
변화도 포함한다. 첫 단계에서는 전체 가격 예측 엔진이 없어도 축 선정과 관찰 신호의
품질을 검토할 수 있다. 정량적 예측 기여 평가는 다음 단계와 연결한다.

| 확인할 점 | 평가 질문 |
|---|---|
| 당시 근거 | 선정 이유가 기준일 이전 자료에서 확인되며 반대 근거도 검토했는가? |
| 시장 연결 | 광범위한 뉴스 주제가 실제 수요·공급·가격에 연결되는 경로를 설명하는가? |
| 관찰 가치 | 결과가 나온 뒤 붙인 이름인가, 그 전에 확인할 구체적 신호를 제안했는가? |
| 시대 적합성 | 중요도·조건·시차가 시대별 시장 구조에 맞는가? |
| 갱신 능력 | 새 정보에 따라 필요한 축을 추가하고 약해진 축을 내리되 사소한 정보에 과잉 반응하지 않는가? |
| 누락과 오경보 | 중요한 경로를 놓쳤거나 영향이 작았던 축을 계속 최우선으로 제시하지 않았는가? |

AXIS에 유일한 정답 목록이 있다고 가정하지 않는다. 동시대 자료와 전문가 검토를 참고하고,
항상 같은 축을 쓰는 방식이나 단순 기사 빈도 기반 선정과 비교한다. 검토 기준과 시험 기간을
먼저 기록하며 결과가 좋았던 시대만 선택하지 않는다. 자료량·매체 범위가 시대마다 다른
문제와 실제 시장 변화에 따른 차이도 구분한다.

**LLM의 과거 지식은 별도 한계다.** 현대 LLM은 기준일 이후 사건을 이미 학습했을 수
있으므로 '그때라고 생각하라'는 지시나 검색 날짜 제한만으로 사후 정보가 제거됐다고
보장할 수 없다. 출처에 근거한 재현 결과와 엄격한 미래 예측 성능 주장을 구분한다.
현재부터 관점·근거·관찰 신호를 저장하고 실제 다음 시점에 평가하는 검증도 함께 설계한다.

화면 기능으로는 Perspectives 안에서 기준 시점을 바꾸어 당시 관점과 선정 근거를
읽고, 다음 시점에 축이 어떻게 갱신됐는지 비교하는 **과거 시점 검토**를 제안한다.
구체적인 자료 확보·채점 방식·실행과 화면 배치는 후속 작업이며 이번에 검증을 완료한 것은 아니다.

방법론 참고:
- [시간 순서를 지키는 검증](https://otexts.com/fpp3/tscv.html): 검증 시점 이후 자료를 학습에 포함하지 않는 원칙.
- [Crane·Karra·Soto, Total Recall? (2025)](https://www.federalreserve.gov/econres/feds/files/2025044pap.pdf): LLM의 통계 개정값·발표 시점·미래 정보 혼입에 관한 연구. 연준 연구진의 작업 논문이며 기관의 공식 입장은 아니다.

## 9. 후속 화면 설계의 완료 기준

아래 질문에 사용자가 막힘없이 답할 수 있을 때 화면 배치를 구체화한다.

- LIORA가 제안한 축을 왜 봐야 하며, 내가 바꾸면 무엇이 달라지는가?
- 과거 시점의 자료로 AXIS를 선정했을 때 그 근거와 당시 관찰 가치를 평가할 수 있는가?
- 각 연결은 상관·예측·인과 중 어떤 근거를 가지며 언제 성립하는가?
- 이 세계는 왜 선정됐고 전체 가능성의 얼마를 포괄하는가? 제외된 것은 무엇인가?
- 가격·수급 범위는 어느 세계와 어느 기준일에 대한 결과인가?
- 과거와 현재 전망이 달라진 이유를 계산과 원문까지 확인할 수 있는가?
- 새 정보가 아직 반영되지 않았는지, 확률·가격을 이미 바꿨는지 알 수 있는가?
- 어떤 신호를 보면 어떤 판단과 대비를 다시 검토해야 하는가?
- 자료나 모형이 부족할 때 지금 할 수 있는 일과 할 수 없는 일을 이해할 수 있는가?

다음 작업은 이 기능 구조에 대해 사용자가 수행할 대표 업무를 확인하고, 각 화면의
입력·핵심 행동·출력·다음 이동을 기준으로 화면 배치를 설계하는 것이다.
현재 문서는 기능 설계이며 모델 계산·프런트엔드·모니터링 자동화의 구현 완료를 뜻하지 않는다.
