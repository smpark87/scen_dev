# Perspectives 첫 제품 구현

작성: 2026-09-23. 범위: **scen_dev 로컬 제품 화면**, 운영 배포 없음.

## 이번에 사용할 수 있는 흐름

1. `US gas / Henry Hub`와 관측 기준일을 선택한다.
2. AXIS 후보를 열어 연결된 사인포스트와 영향 경로 **가설**을 탐색한다.
3. 실제 관측값, 전년 동월 차이, 월별 그래프, 출처·수집시각·집계 입력 수를 확인한다.
4. 모니터링할 축과 연구 메모를 선택해 이름 있는 관점을 저장한다.
5. 저장 목록에서 다시 열면 **저장 당시 관측과 가설 목록**을 본다. DB가 바뀌어도 해당 관점은 바뀌지 않는다.

Perspectives → Projections → What If 순서를 유지한다. 뒤의 두 탭은 계획 단계로 표시되며 예측·확률·가격 범위를 생성하지 않는다. OUTLOOK 아이콘은 망원경이다.

## 실행

저장소 루트에서 PowerShell:

```powershell
..\shared\.venv\Scripts\python.exe -m pip install -r ..\shared\requirements.txt -c ..\shared\requirements.lock
..\shared\.venv\Scripts\python.exe -m outlook
```

`http://127.0.0.1:8765/perspectives`를 연다. 기존 `SCEN_DATABASE_URL` 설정을 사용한다. 값은 `.env`에 유지하고 문서·로그·커밋에 넣지 않는다.

종료는 실행한 터미널에서 Ctrl+C. Waitress는 loopback에만 바인딩하며 Flask 디버거를 켜지 않는다. 인증·운영 호스팅은 이번 범위가 아니므로 외부 주소로 바인딩해 공유하지 않는다. 실제 배포는 대상·범위를 사용자에게 제시하고 별도 명시적 승인을 받은 뒤에만 진행한다.

## 데이터와 관점의 경계

- 모든 원천 조회는 `outlook/evidence.py` → `db.connect()`의 읽기 전용 연결을 사용한다. 새로운 수집 job이나 DB 쓰기는 없다.
- `market_indicators`의 허용된 11개 지표, 기준일 이전 800일을 바인딩된 SQL로 읽는다. 쿼리 제한시간은 15초, 동일 기준일 조회는 최대 2분간 재사용한다. 실패 결과는 캐시하지 않는다.
- 운영 DB의 원천 데이터는 하나로 유지한다. `data/outlook/perspectives/*.json`은 사용자가 선택한 축·메모와 그때 본 분석 결과를 보존하는 **로컬 연구 스냅샷**이다. 재수집용 DB나 운영 계열의 대체 저장소가 아니다. `data/`는 Git 제외 대상이다.
- 저장은 브라우저에 표시했던 서버 측 초안에서 수행한다. 저장 시 다시 조회하지 않는다. 초안은 세션에 연결되고 최대 1시간/128개까지 유지되며, 만료되면 재조회 안내를 표시한다.
- 원자적 파일 교체로 저장하며 임의 경로를 받지 않는다. 저장한 관점의 수정·삭제·다중 사용자 공유는 아직 구현하지 않았다.

## 관측 규칙

| 유형 | 완료 월 집계 | 최소 포함 기준 |
|---|---|---|
| Platts 일별 유량 | 월평균 | 달력일의 90% 이상, 첫 관측 4일 이내·마지막 관측 월말 3일 이내 |
| ECB 환율 | 관측 영업일 월평균 | 18일 이상, 첫 관측 6일 이내·마지막 관측 월말 5일 이내 |
| EIA 저장량 / Baker Hughes rig | 월의 마지막 관측값 | 3회 이상, 첫 관측 8일 이내·마지막 관측 월말 7일 이내 |
| NOAA HDD/CDD | 월별 원값 | 완료 월의 관측 1개 이상 |

- 진행 중인 달은 제외한다. 최근 값이 직전 완료 월보다 오래되면 `Lagging`으로 표시한다.
- 정확히 같은 출처·단위만 사용한다. Baker Hughes의 다른 이름 계열을 자동 합치지 않는다. 같은 관측일의 중복은 기준일 필터를 통과한 가장 늦은 수집본 하나를 사용한다.
- NaN/무한대/단위 오류/불충분한 월은 수치로 표시하지 않는다. 유효성·월 충족도 때문에 제외된 입력 수를 출처 상세에 표시한다. 다른 출처·기간 밖 행·진행 월 제외는 이 수에 포함하지 않는다.
- 변화는 전년 **동월 값과의 절대 차이**다. p-value, 인과효과, 중요도, 확률이 아니다. 비교 월이 없으면 차이를 생성하지 않는다.
- 그래프는 최대 24개 완료 월을 표시하고, 빠진 달을 선으로 연결하지 않는다. 축 사이의 그래프 범위는 서로 다르다.
- Texas HDD/CDD는 미국 전체 기상 지표가 아니다. LNG feedgas는 LNG 수출량이 아니다. EUR/USD는 달러지수가 아니다. 생산량의 dry/marketed 정의는 확인 과제로 남겼다.

## 역사적 검증에 대한 제한

관측일 `period`와 수집일 `fetched_at` 모두 기준일 이전인 행만 사용한다. 하지만 현 DB의 수집시각은 원자료 발표시각과 같지 않고, 과거 버전이 수정·덮어쓰기 되었을 수 있다. 시간대 없는 `fetched_at`은 DB에 기록된 달력일 기준으로 비교한다. **이 필터는 진정한 과거 시점 복원을 보장하지 않는다.**

1980·1990·2000년을 조회할 수 있지만 당시 자료가 확인되지 않으면 빈 상태를 표시한다. 오늘 만든 여섯 축을 그 시대의 발견 결과로 부르지 않는다. 현대 LLM의 역사 지식 오염 문제도 해결되지 않았다.

AXIS 후보 여섯 개는 제품 흐름을 검토하기 위한 초기 연구 가설이다. 자동 선별·중요도 순위·상관 검정·시차 검정·인과 판정은 아직 없다. 관측 지표 수를 중요도 점수로 바꾸지 않는다. 정량 자료가 없는 정책/프로젝트 축도 남겨 놓는다.

## 다음 구현 순서

1. **AXIS를 제안하고 검토하는 실제 작업 흐름:** 후보 생성 근거, 채택/보류/기각 이유, 사용자 수정, 지표와 문서 근거의 연결.
2. **과거 평가 기반:** 원자료 발표시점·버전·문서 가용성을 기록하는 evidence manifest, 기준일별 재생 자료집, 결과를 보기 전에 고정하는 평가 기준. 과거 자료가 부족한 구간과 LLM 사전지식 한계를 구분한다.
3. **관계 검증:** 단순 상관 / 시차 예측력 / 인과 근거를 구별해 저장·표시하고, 시대와 시장에 따른 안정성을 검증한다.
4. 검토 가능한 Perspectives가 쌓인 뒤, 사인포스트별 모델과 확률 가지를 연결하는 Projections로 확장한다.

이 순서는 `docs/14-outlook-functional-architecture.md`의 단계 구분을 따른다. 이번 UI의 여섯 후보가 최종 AXIS 체계로 굳어지는 것은 아니다.
