# 내부 개발의 근거

> **핵심 논지:** 이 시스템은 외주로 만들 수 없는 종류이며,
> **그 이유가 정확히 내부에서 만들어야 하는 이유다.**
> 비용 절감은 결과이지 논거가 아니다.

---

## 1. 요약

| | 외부 발주 | **내부 개발** |
|---|---|---|
| 설계 단계 | 3~4개월 / 4~5명 / **1~6억** | **완료** (문서 00~05) |
| 구현·검증 | 12~18개월 / 7~12명 / **5~25억** | **3~6개월 / 소수 인원** |
| 직접 비용 | — | **인프라 220~330만원 + AI 개발도구 구독료** |
| **총 투입** | **5~25억** | **약 300~500만원** |

> **그러나 핵심은 금액이 아니라 — 이 과제가 외주로는 작동하지 않는다는 점이다 (§4).**
> 비용 차이는 결과이지 논거가 아니다.

## 3. 지금까지의 설계 산출물을 발주 기준으로 환산하면

`00-charter` ~ `04-infrastructure`는 컨설팅 프로젝트의 **진단·설계 단계 산출물**에
해당한다. 통상적인 발주 규모:

| 항목 | 통상 |
|---|---|
| 기간 | 3~4개월 |
| 인원 | 4~5명 (PM · 데이터 아키텍트 · 모델러 · 도메인) |
| 금액 | 대형 컨설팅펌 **3~6억** / 중견 **1~2억** |

**이 단계가 이미 끝나 있다.** 그리고 §5에서 보듯, 발주로는 나오기 어려운
내용이 포함되어 있다.

### 3.1 전체 구현을 발주했다면

| 발주 형태 | 인원 | 기간 | 예상 견적 |
|---|---|---|---|
| 대형 컨설팅펌 (전략+구현) | 8~12명 | 12~18개월 | **25~50억** |
| 중견 SI / AI 전문업체 | 7~9명 | 12~15개월 | **10~18억** |
| 소규모 전문 부티크 | 4~5명 | 12개월 | **5~8억** |
| 파일럿 범위만 (Phase 0+1) | 3~4명 | 6개월 | **2~3.5억** |

필요 직군: PM 1 · 데이터 엔지니어 2~3 · **ML·통계 모델러 2~3** ·
**에너지 시장 도메인 1~2** · 인프라 1 · 프론트 0.5

> ※ 국내 MM 단가 기준 개략 추정. 업체·계약형태에 따라 편차가 크다.

## 4. 그런데 이 프로젝트는 외주로는 작동하지 않는다 — 네 가지 이유

### 4.1 핵심 산출물이 계약 시점에 미지다

외주 계약은 *"무엇을 만들어 검수받는다"* 이다. 그런데 이 시스템의 핵심 활동은:

```
정성 변수가 잔차화·증분검정을 통과하는가 (03 §5.8)
Signpost가 실제로 선행하는가            (01 §8)
시나리오 연결에 근거가 있는가            (01 §6.3)
```

**전부 결과를 계약 시점에 알 수 없는 연구 활동이다.** 고정가 계약과 구조적으로
맞지 않는다.

### 4.2 "실패"가 정당한 결과여야 하는데, 벤더에겐 납품 실패다

헌장 §7.4는 **"틀렸다는 결과가 나올 수 있음을 사전에 합의한다"** 고 규정한다.
04 §10.5는 판정을 **확대·유지·중단** 3지선다로 두고 "중단"을 정당한 결론으로 둔다.

**벤더는 이 조항을 쓸 수 없다.** 자기 계약을 스스로 위험에 놓는 조항이기 때문이다.
계약 구조상 벤더는 **통과하도록 맞추게 된다** — 그 순간 이 시스템은 무의미해진다
(헌장 §7.4가 금지하는 바로 그것).

> **이 문서들은 발주자만 쓸 수 있는 문서다.**

### 4.3 도메인 인력이 시장에 사실상 없다

미국 가스·LNG 시장의 미시구조 — basis 형성, EBB 유지보수 공지의 가격 영향,
FERC/DOE 규제 창, LNG netback, 체제전환 이력 — 를 아는 모델러는 국내에 극소수다.

벤더는 십중팔구 **이 부분을 발주자 인력에 의존하는 전제로 견적을 낸다.**
그러면 실질 부담은 줄지 않으면서 비용만 발생한다.

### 4.4 기존 자산 위에 설계되어 있다

이 설계는 `ngip_dev`의 실물을 전제로 한다 — RAG 코퍼스, FERC 인제스터, ICE 피드
파이프라인, PostGIS 자산, LIORA 툴 구조, Estimation 워크스페이스.

**외부 벤더는 신규 구축을 전제로 견적을 낸다.** 재사용 판단을 하려면 기존 시스템을
먼저 파악해야 하고, 그 자체가 수개월의 비용이다.

## 5. 발주로는 나오기 어려운 내용 — 문서에 이미 들어 있는 것

단순히 "우리가 먼저 썼다"가 아니라, **발주 구조에서는 생성되기 어려운 성격**의 내용이다.

| 내용 | 왜 발주로는 안 나오는가 |
|---|---|
| **실패 조건의 사전 정의** (04 §10.3~10.5) | 벤더는 자기 실패 조건을 계약서에 쓰지 않는다 |
| **비용이 검증을 따라가는 구조** (Phase 0 → 최소 → 표준) | 벤더는 반대로 설계한다 — 선투자 후 산출 |
| **실측 기반 산정** (청크당 20.7 KB, RDS 사양, `hub_prices` 실태) | 제안서는 "일반적으로 ~정도"로 쓴다. 우리는 DB를 열어보고 썼다 |
| **범위 축소의 근거** (사내 데이터·포트폴리오 층 제외) | 벤더는 범위를 넓힐 유인이 있지 좁힐 유인이 없다 |
| **AI 서사의 위험 인식** (01 §6.4 소설 생성기 방지) | AI 도입 제안서가 AI의 실패 양식을 중심에 두기는 어렵다 |
| **도메인이 내장된 데이터 카탈로그** (03) | §4.3의 인력 문제 |

## 6. 왜 3~6개월에 가능한가 — 근거

"1명이 6개월에 한다"는 주장은 그 자체로는 신뢰하기 어렵다. 근거를 제시한다.

### 6.1 이미 작동하는 증거가 있다

**§2 참조.** `ngip_dev`가 동일한 방식으로 2.7개월 만에 구축되어 운영 중이며,
이 프로젝트가 요구하는 기술 요소 — RAG·벡터·자동수집·PostGIS·LLM 툴 오케스트레이션 —
대부분이 거기서 이미 구현·검증되었다.

"할 수 있는가"는 답이 나와 있고, 남은 것은 **"이 주제에 적용하는가"** 다.

### 6.2 전통적 개발의 병목이 여기엔 없다

대규모 SI 프로젝트의 기간 대부분은 **코딩이 아니라 소통과 이전**에 쓰인다.

| 통상 병목 | 이 프로젝트 |
|---|---|
| 도메인 지식을 개발팀에 이전 | **없음** — 도메인 보유자가 직접 구현 |
| 요구사항 정의·합의·변경관리 | **없음** — 발주자와 구현자가 동일 |
| 팀 간 인터페이스 조율 | **없음** |
| 기존 시스템 파악 | **없음** — 자기 시스템 |
| 산출물 검수·수정 반복 | **없음** |

7~12명 프로젝트의 상당 부분은 **인원이 많아서 생기는 비용**이다. 도메인과 구현이
한 사람 안에 있고 AI 도구가 구현 속도를 받치면, 그 비용이 통째로 사라진다.

### 6.3 이 문서들 자체가 속도의 증거다

`00`~`05` 문서 세트 — 헌장, 개념 정의, 아키텍처, 100여 항목 데이터 카탈로그,
실측 기반 인프라 산정 — 는 통상 발주 시 **3~4개월 / 4~5명**이 걸리는 산출물이다.
**이 문서들이 만들어진 실제 시간이 그 비교의 근거다.**

### 6.4 다만 줄일 수 없는 것도 있다 — 정직하게

3~6개월은 **개발 기간**이지 전체 일정이 아니다.

| 줄지 않는 것 | 이유 |
|---|---|
| **벤더 데이터 백필 리드타임** | 계약·전달에 걸리는 시간은 개발 속도와 무관 |
| 사내 승인·예산 절차 | |
| 라이브 운영 신뢰 누적 | 채점이 쌓이는 데는 시간이 필요 (hold-out 평가는 즉시 가능하나 실전 신뢰는 별개) |

**Phase 0은 벤더 의존이 없으므로 이 제약을 받지 않는다** — 6~8주에 착수·완료 가능하다.

## 7. 내부 개발이 만드는 것 — 금액 외의 가치

### 7.1 조직에 남는 역량

외주는 **시스템**을 남기고, 내부 개발은 **시스템 + 역량**을 남긴다.
특히 이 프로젝트에서 결합되는 것은:

```
에너지 시장 도메인  ×  데이터·AI 방법론
```

이 결합은 국내에서 확보하기 어렵고(§4.3), 한 번 만들어지면 **다음 과제에 재사용된다** —
G2P 진입 판단, 가스전 확장, 포트폴리오 운영으로 순차 확장하는 것이 원래 계획이다
(헌장 §2).

### 7.2 정직한 판정이 가능하다

§4.2의 이면이다. 발주자 스스로 만들면 **"안 되더라"를 결론으로 낼 수 있다.**
그 자유가 있어야 04 §10.3의 판정 기준이 실제로 작동한다.

**부정적 결과도 자산이다** — "정성 정보의 의미기반 활용이 이 시장에서는 증분을
주지 못한다"는 결론이 6~8주 만에 0원으로 확인되면, 그것 자체가 향후 수억 원의
잘못된 투자를 막는다.

### 7.3 기존 투자의 활용

`ngip_dev`에 이미 축적된 것 — 코퍼스 파이프라인, FERC 인제스터, ICE·Platts 피드,
가격 DB, LIORA — 이 그대로 재사용된다. **신규 구축이 아니라 확장이다.**

## 8. 정직하게 — 내부 개발의 위험

논거의 신뢰를 위해 함께 밝힌다.

| 위험 | 대응 |
|---|---|
| **인력 집중 (버스 팩터)** | 최대 위험. 대응은 **문서화이며 이미 확보되어 있다** — 00~05가 설계·근거·판정기준을 담고 있어, 담당자가 바뀌어도 재개 가능. 코드보다 **왜 그렇게 설계했는가**가 남는 것이 핵심 |
| **본업 병행에 따른 지연** | 전업이 아니면 3~6개월이 늘어날 수 있음. Phase 0(6~8주)의 짧은 게이트로 조기에 실현성 확인 |
| **전문 영역의 깊이** | 상태공간·분포추정 등은 필요 시 **전문가 자문 계약**(파트타임 1명)으로 보완 — 전체 발주 대비 극히 저렴 |
| **품질 검증** | AI 보조 개발의 산출물 품질 우려 → 이 설계는 **과정이 아니라 결과로 검증**한다. E1~E11 실증과 상시 채점(헌장 §7.1)이 그 장치이며, 통과하지 못하면 중단이 정당한 결론이다 (04 §10.5) |
| 객관성 | 자기 프로젝트를 스스로 평가하는 문제 → **판정 기준 사전 동결**(헌장 §7.4)이 방어 장치 |

### 8.1 그래서 권하는 형태 — 분할

**전부 내부**가 아니라, 성격에 따라 나눈다.

| 영역 | 방식 | 이유 |
|---|---|---|
| 데이터 수집 파이프라인 | **외주 가능** | 명세 명확(03), 검수 가능. 반복 작업 |
| 인프라 구축·배포 | **외주 가능** | |
| UI (Estimation 캔버스) | **외주 가능** | 산출물 형태 확정 후 |
| **변수 설계·검증** | **내부** | 결과 미지 (§4.1) |
| **모델 구조 결정** | **내부** (+ 전문가 자문) | |
| **시나리오 채택 기준** | **내부** | 도메인 판단 (§4.3) |

이 구분이면 **외주 범위는 1~2억 수준**(파이프라인·인프라·UI)으로 떨어지고,
그마저도 Phase 1 이후로 미룰 수 있다.

## 9. 보고용 한 문단

> 본 과제는 설계 문서를 이미 확보한 상태입니다. 동일 범위를 외부에 발주할 경우
> **진단·설계 단계만 1~6억, 전체 구현은 5~25억 / 12~18개월 / 7~12명** 규모로
> 추정됩니다. **내부 개발 시 3~6개월, 직접비용은 인프라 220~330만원과 AI 개발도구
> 구독료 수준입니다.**
>
> 다만 **비용보다 중요한 것은 이 과제가 외주에 적합하지 않다는 점**입니다.
> 핵심 활동인 "정성 정보가 실제로 예측력을 더하는가"의 검증은 **결과를 계약 시점에
> 알 수 없어** 고정가 계약과 맞지 않으며, **"성립하지 않는다"는 결론이 정당한
> 결과여야 하는데 수주 업체에게는 납품 실패**가 됩니다. 미국 가스·LNG 시장
> 도메인 인력도 국내에 사실상 부재합니다.
>
> 기간 단축의 근거는 **기존 운영 시스템(ngip_dev)이 동일한 방식으로 구축되어 이미
> 가동 중**이라는 점입니다 — RAG 코퍼스, FERC 자동수집, 가격 파이프라인, PostGIS
> 지도, LIORA 어시스턴트가 모두 여기에 해당하며, 본 과제가 요구하는 기술 요소
> 대부분이 이미 구현·검증되어 있습니다. 또한 **도메인 보유자가 직접 구현**하므로
> 대규모 프로젝트 기간의 상당 부분을 차지하는 요구사항 이전·조율·검수 비용이
> 발생하지 않습니다.
>
> **Phase 0는 추가 비용 없이** 착수 가능하며, 여기서 방법론이 성립하지 않으면
> **외부 데이터 구매 전에 중단**할 수 있습니다. 성과와 별개로 **에너지 도메인과
> 데이터·AI 방법론이 결합된 역량이 조직에 남으며**, 이는 후속 과제(G2P 진입,
> 가스전 확장, 포트폴리오 운영)에 재사용됩니다.
>
> 수집 파이프라인·인프라·UI 등 명세가 확정된 영역은 필요 시 **분할 발주**가
> 가능하며, 그 범위는 1~2억 수준으로 축소됩니다.
