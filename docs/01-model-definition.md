# 개념 정의와 모델 골격

> 헌장(`00`) §9가 지목한 미정의 항목을 해소한다.
> **v2.0 변경:** v1.0은 "시나리오 = 관계 구조가 유지되는 영역"으로 정의했으나, 이는
> 현재 시장을 서술하는 **Regime**의 정의였고 미래 경로로서의 **Scenario**와 혼재되어
> 있었다. 이 혼재가 확률의 의미·Signpost 정의·AI 역할·산출 스키마로 연쇄 전파되므로
> 개념을 분리하고 하나의 체계 안에서 다시 연결한다.

## 1. 개념 분류 — 다섯 층

### 1.1 왜 분리하는가

두 개념은 **인식론적 성격이 다르다.**

- **Regime**은 관측된 데이터로 *추정*하는 대상이다. "지금 시장이 어떤 구조에 있는가"
- **Scenario**는 *구성하고 검증*하는 대상이다. "앞으로 어떤 사건과 반응을 거쳐
  어디로 갈 것인가"

데이터는 앞으로 어떤 정책·지정학·사업 사건이 발생할지, 참여자가 어떤 순서로 반응할지,
제도적 제약이 어떤 경로를 허용할지를 스스로 알 수 없다. 이 둘을 하나의 객체로 다루면
확률의 의미가 무너지고("현재 이 Regime일 확률"과 "미래 이 경로가 실현될 확률"이 같은
컬럼에 들어간다), AI의 해석이 곧 미래 예측인 것처럼 취급된다.

### 1.2 다섯 개념

| 개념 | 정의 | 성격 |
|---|---|---|
| **Market State** | 현재까지 관측된 정보로 추정한 시장의 현재 상태 (연속 좌표) | 추정 |
| **Regime** | 변수 간 관계와 시장 작동방식이 비교적 안정적으로 유지되는 구조적 국면 | 추정 |
| **Transition** | 현재 Regime의 유지·약화·전환 가능성과 전환 경로 | 추정 |
| **Scenario** | 주요 동인과 사건이 현실적 인과경로를 따라 행위자 반응과 시장 결과로 이어지는 **조건부 미래 경로** | **구성 + 검증** |
| **Conditional Outlook** | 각 Scenario 전개 시 예상되는 가격·Basis·Spread·Netback·변동성 등의 분포 | 추정 (조건부) |

### 1.3 처리 흐름

```
1. 상태공간 추정          (Market State — nowcast 포함)
2. Regime 식별            현재 어떤 구조적 국면인가
3. Transition 평가        유지 / 약화 / 전환 가능성 + 시계
4. Scenario 구성·검증·채택  조건부 미래 경로 (연결 단위 심사)
       ├─ 5. Signpost 설정     각 Scenario의 전제를 관측 가능한 조건으로 분해
       └─ 6. Conditional Outlook   Scenario별 분포 + 가중 혼합분포

   ※ 1~3은 데이터가 추정. 4는 구성·검증. 5~6은 4에서 파생.
```

AI가 Regime을 서사로 번역하는 것은 **현재 상태의 해석**이며, 그 자체가 미래 Scenario의
생성이 아니다. 이 구분이 §6.4(서사는 증거가 아니다)의 출발점이다.

### 1.4 표기 규약 — 확정 수준 3단계

이 문서와 이후 산출물은 각 항목의 확정 수준을 구분해 표기한다. 초기 단계에서 과잉
확정은 실증 결과가 설계를 수정해야 할 때 장애가 된다.

| 태그 | 의미 |
|---|---|
| **[원칙]** | 쉽게 바꾸지 않는 설계 철학. 변경하려면 헌장 개정 수준의 논의 필요 |
| **[가설]** | 실증으로 검증·기각 가능한 판단. 기각되어도 체계는 성립 |
| **[선택]** | 현재 조건에서 택한 방법. 더 나은 대안이 확인되면 교체 |

## 2. Regime 층

### 2.1 정의 **[원칙]**

> **Regime = 변수 간 인과·관계 구조가 안정적으로 유지·연결되는 시장상태의 영역.**
> **Regime 전환 = 그 구조가 바뀌는 것.**

가격 수준의 구간이 아니라 "변수들이 서로 어떻게 작동하는가"가 이어지는 영역이다.
평상시에는 저장량 증가가 가격을 누르지만 공급위기 국면에서는 저장량이 신호로 기능하지
않고 다른 관계가 지배한다 — 이 **관계의 재편**이 Regime 전환이다.

원문서 정합: 전략문서의 *"Correlation Breakdown Risk를 별도로 측정"*, 추진안의
*"Base Case의 전제가 훼손"* 이 모두 이 개념을 가리킨다.

### 2.2 3층 구조 **[원칙]** — 축 강제 금지

축을 미리 정해 줄이는 것을 금지한다. 2축 사분면은 과거 시나리오 플래닝으로의 회귀다 —
당시 2축이었던 이유는 옳아서가 아니라 사람이 그래야만 이해할 수 있어서였다.
다차원을 다룰 수 있다는 것이 AI와 함께 하는 이유다.

```
① 상태공간   정형변수 + Semantic Factor. 고차원. 축을 미리 정하지 않음
      ↓
② Regime     그 공간에서 관계 구조가 유지되는 영역(모드).
             개수도 위치도 데이터가 정함. 생기고 사라짐
      ↓
③ 해석       각 Regime이 무슨 상태인지 AI가 서사로 번역
             예: "공급충격 + 정책 불확실성 + 아시아 수요 약세가 동시에 있는 국면"
```

- 2축 시대에는 해석이 공짜였다(그림으로 읽히니까). 고차원에서는 해석을 **생성**해야
  하며, 그것이 ③층 = AI의 역할이다. ②가 유기성을, ③이 이해가능성을 담당한다
- ③의 서사는 검증 대상이다: 서사에서 상태를 복원할 수 있는가, 서사가 함의하는 변수
  움직임이 실제와 맞는가 (E5 양방향 검사). **단, 이는 설명의 정합성 검증이며
  미래 경로의 개연성 검증이 아니다** — 후자는 §6.3의 몫
- 전략문서의 4개 시장상황은 **초기 해석 틀**로만 쓴다. 실제 Regime이 그 사분면과
  다르면 그것이 발견이다

### 2.3 Regime의 생성·소멸 — surprise는 진단 트리거 **[원칙]**

기존 Regime으로 설명되지 않는 잔차(예측분포 대비 놀라움)가 지속적으로 쌓이는 것은
중요한 신호다. 시스템이 스스로 **"지금 내 틀 밖의 일이 벌어지고 있다"** 고 말하는
기능이며, 확률을 잘 맞히는 것보다 값질 수 있는 출력이다.

**그러나 큰 잔차가 곧 신규 Regime은 아니다.** 가능한 원인이 여럿이므로 순차 진단한다:

```
지속적 잔차 발생
   ↓ 순차 배제
① 데이터 오류·수집 지연  ② 측정방식 변경  ③ 일회성 Shock
④ 기존 변수의 누락       ⑤ 파라미터 Drift  ⑥ 기존 Regime 내 극단값
   ↓ 모두 배제되고
⑦ 통계적 지속성·재현성 + Domain 검토 통과 → 신규 Regime 채택
```

- surprise 수준 자체는 일급 산출물로 상시 공개한다 (헌장 §7.1 채점의 핵심 지표)
- 재추정할 때마다 Regime이 뒤바뀌면 쓸 수 없다 — 시간적 지속성을 명시적으로
  모델링한다 (E3, E10)

## 3. 시간 구조 — 상태공간과 필터링

혼합 주기·발표 지연·개정·시간 스케일 문제를 **하나의 구조**로 처리한다. **[선택]**
(상태공간·필터링 계열을 채택. 구체 기법은 Phase2에서 비교·선정)

### 3.1 원리 — 변수를 서로 맞추지 않는다

상태는 하나의 시계(일별)로 연속 진화하고, 각 변수는 자기 주기·자기 시점에 그 상태를
**부분 관측**한 것으로 취급한다.

```
상태 (일별 진화):   s₁ → s₂ → s₃ → s₄ → s₅ → s₆ → s₇ → …
                     ↑         ↑            ↑
관측:            가격(매일)  뉴스(불규칙)  저장량(목요일,   생산량(월말,
                                          지난주 값)      2달 전 값)
```

- 관측이 없는 날은 문제가 아니다 — 갱신 없이 상태가 전파될 뿐. 주기를 맞추는 작업
  자체가 사라진다 (전부 월별로 뭉개는 집계 방식을 기각하는 이유)
- 관측마다 신뢰도를 다르게 준다: 속보치는 노이즈 크게, 확정치는 작게
- **개정치는 같은 기간에 대한 추가 관측**으로 들어간다 — 헌장 §6.4(bitemporal)와 맞물림

### 3.2 발표 지연은 결함이 아니라 입력이다 (nowcast)

"EIA 월간 생산량이 2달 늦게 온다" = 오늘의 상태 추정에 그 관측이 아직 도착하지 않았다
(ragged edge). 공식 통계가 오기 전까지 **같은 상태를 관측하는 고빈도 프록시가 빈자리를
메운다** — 파이프라인 일별 flow, rig count, 처리량이 생산 상태를 계속 관측하고, 두 달 뒤
공식치가 도착하면 소급 보정된다.

1. **"현재 상태의 nowcast" 자체가 시스템 산출물이다.** "공식치는 5월분까지지만 파이프
   flow 기준 7월 생산은 이미 꺾이고 있다" — 이 문장을 상시로 내놓는다
2. **고빈도 프록시의 수집 우선순위가 올라간다.** 어느 프록시가 어느 공식 통계를
   선행하는지의 짝 구조를 데이터 명세에 명시한다
3. **`observed_at` 없이는 이 구조를 학습할 수 없다.** bitemporal은 백테스트 규율이
   아니라 모델 성립 조건이다

### 3.3 시간 스케일의 분해 **[가설]**

헌장 §2의 판단들은 일~주(헤지)부터 년~십년(장기계약)까지 걸쳐 있고, 시장 상태는 이
스케일들에 동시에 존재한다. 하나의 상태에 다 넣으면 일간 기상 노이즈가 구조 전환
신호를 덮는다.

```
s(t) = s_구조(t) + s_계절(t) + s_단기(t)
        분기~년       연중        일~주
```

- §2.1의 "구조 변화"는 **s_구조 수준의 관계 재편**이다. 단기 성분의 요동은 Regime
  전환이 아니다
- 단기 충격의 반복이 구조를 바꾸는 경로(2021–22형)는 s_단기의 지속적 이상이
  s_구조로 전이되는 것으로 표현된다
- **3분해는 가설이다.** 성분 수와 경계는 Target·시계에 따라 달라질 수 있으며 E2에서
  검증한다

## 4. 변수의 역할과 상태 차원 학습

### 4.1 Semantic Factor의 위치 **[원칙]**

정성정보의 의미를 통계변수로 쓰는 것은 이 프로젝트의 핵심 역량이다(헌장 §5.2).
다섯 층 구조에서 Semantic Factor가 작동하는 지점을 명시한다:

| 층 | Semantic Factor의 역할 |
|---|---|
| Market State | **상태공간의 좌표 구성 요소** (정형변수와 나란히) |
| Regime | **식별 입력** — 관계 구조 판별에 참여 |
| Transition | **전환 신호 원천** |
| Scenario | 직접 들어가지 않음 — 후보 제안과 근거 회수에 활용 |
| Conditional Outlook | 조건부 분포의 설명변수 |

압축은 필요하나 대립 서사를 상쇄시켜서는 안 된다 — 단순 차원축소는 강세 서사와 약세
서사가 동시에 강한 상태를 "중립"으로 만든다. Factor화는 서사 클러스터를 분리한 뒤 각
클러스터의 강도를 따로 재는 구조여야 한다. **[원칙]**

### 4.2 H1 — 변수군의 역할 분화 **[가설]**

> **H1: 정형변수와 Semantic Factor는 정보 생성 방식과 시장 반영 방식이 다르므로,
> 현재 상태 설명력과 전환 예고력이 서로 다를 가능성이 있다.**
> 역할을 사전에 고정하지 않고, **Target 및 시계별로 선행성·증분 설명력을 실증 검증한다.**

v1.0은 "정형=좌표, Semantic=선행신호"로 역할을 나누고 그 근거를 "뉴스의 의미는 시장이
소화하는 데 며칠~몇 주가 걸린다"로 설명했으나, **이 근거는 일반화할 수 없다** — 중요한
뉴스는 수초~수분 내 반영되고, 반대로 일부 정형변수(설비·생산 계획)는 구조 변화를
선행한다. Semantic Factor도 선행신호뿐 아니라 이미 가격에 반영된 Narrative를 측정하는
역할을 할 수 있다.

상호작용이 중요할 가능성이 높다 — 저장량이 낮은 상태에서의 공급차질 뉴스는 효과가
증폭된다. E1에서 검증한다.

### 4.3 상태 차원의 학습 **[선택]**

- 순수 비지도(관측변수 압축)의 함정: 분산이 큰 방향이 시장에 중요하다는 보장이 없다.
  뉴스가 많은 주제 ≠ 시장을 움직이는 주제
- 순수 지도(점추정 가격 설명력)의 함정: 이미 가격에 반영된 것만 잡는다

**절충: 지도학습으로 하되 목표를 점추정이 아니라 분포 전체로 잡는다.** 다만 학습·선정
기준은 꼬리 하나가 아니라 다음을 **함께** 본다:

```
Target별 분포 예측력  ·  전환 탐지력  ·  Tail Risk 포착력  ·  해석 안정성
```

> v1.0의 *"시나리오는 본질적으로 꼬리에 관한 것"* 은 과한 표현이었다. Scenario에는
> 중심 경로의 구조적 변화, 점진적 수급 전환, 가격 수준보다 Basis·Spread 구조가
> 달라지는 경로, 발생 가능성은 높으나 영향이 누적되는 변화도 포함된다. 꼬리는 중요한
> 학습 목표이지 Scenario 전체와 동일하지 않다.

표본 제약(국면 13~14개, 헌장 §6.2)은 축 강제가 아니라 **구조 부과**로 대응한다:
희소성·계층·저랭크 제약. **분리의 부수 이득** — Regime은 일별 관측으로 추정하고
Scenario는 통계 추정 대상이 아니므로, 국면 수 제약은 Regime 층에만 적용된다.

---

## 5. Transition 층 **[원칙]**

현재 Regime이 유지될지, 약화되는지, 어디로 전환될 가능성이 있는지를 평가한다.
Regime 층(현재)과 Scenario 층(미래 경로) 사이의 다리다.

산출:
- 현재 Regime의 **안정성 지표** (관계 구조가 얼마나 견고한가)
- **전환 확률과 시계** — "향후 N개월 내 전환 가능성" (시계 없는 전환확률은 무의미)
- **후보 전환 방향** — 어느 Regime으로 갈 가능성이 있는가
- 전환을 선행하는 관측변수 (= Regime Transition Indicator, §8의 Signpost 한 유형)

Transition은 데이터가 추정한다. Scenario와 달리 도메인 구성 대상이 아니다.

---

## 6. Scenario 층

### 6.1 정의 **[원칙]**

> **Scenario = 주요 동인과 사건이 현실적인 인과경로를 따라 행위자 반응과 시장 결과로
> 이어지는 조건부 미래 경로.**

Regime이 "지금 어떤 구조인가"라면 Scenario는 "앞으로 무엇을 거쳐 어디로 가는가"다.

### 6.2 후보 생성과 채택 — 두 축의 만남 **[원칙]**

> **Data·AI는 새로운 Regime, Transition Signal 및 Scenario 후보를 탐색하고,
> Domain은 사건의 전개경로와 행위자 반응을 구성·검증한다.
> Scenario는 두 축의 검증을 거쳐 채택·수정·퇴장한다.**

이 시스템은 완전한 데이터 주도도 아니고, 사람이 미리 정한 목록을 기계적으로
모니터링하는 방식도 아니다. **Domain-led hypothesis와 Data-led discovery가 반복적으로
만나는 구조**다.

데이터가 할 수 있는 것 / 없는 것:

| 데이터가 발견할 수 있는 것 | 데이터만으로 확정하기 어려운 것 |
|---|---|
| 현재 상태가 기존 Regime 중 어디에 가까운지 | 앞으로 어떤 정책·지정학·사업 사건이 발생할지 |
| 기존 관계구조가 약화되고 있는지 | 참여자들이 어떤 순서로 반응할지 |
| 과거와 다른 변수 조합·잔차의 출현 | 제도·계약 제약이 어떤 경로를 허용·차단할지 |
| 특정 사건 이후 시장 반응이 과거와 달라졌는지 | 어떤 미래 경로가 사업 판단에 의미 있는지 |

**⚠ 회귀 방지 가드레일 [원칙]**
"Domain이 구성·검증"을 문자 그대로 적용하면 사람이 쓴 소수 목록으로 되돌아가 2×2
시나리오 플래닝이 부활한다. 이를 막기 위해:

- **후보 생성은 기계적·조합적으로 수행한다.** Regime·Transition·Signpost 상태와
  사건 유형의 조합에서 후보를 대량 생성하고, Domain은 **저자가 아니라 심사자**다
- **살아있는 Scenario 수에 인위적 상한을 두지 않는다.** 4개로 수렴하면 사분면 회귀다
- Domain 검증은 후보를 **거르는** 게이트이지 후보를 **만드는** 공정이 아니다

### 6.3 채택 — 심사 단위는 Scenario가 아니라 **연결(Link)** **[원칙]**

"이어질 수 없는 것을 잇는" 실패는 Scenario 전체가 아니라 **연결 하나**에서 발생한다.
설득력 있는 전체 서사 안에 근거 없는 화살표 하나가 숨는 방식이다. 따라서 심사 단위를
연결로 내린다. Scenario 전체를 통째로 평가하면 그 화살표가 보이지 않는다.

#### 6.3.1 Scenario의 분해

```
동인 ──▶ 사건 ──▶ 행위자 반응 ──▶ 전달경로 ──▶ 시장 결과
    (링크)   (링크)      (링크)       (링크)

각 화살표 = 하나의 연결(link). 심사는 연결마다 독립적으로.
Scenario의 지위는 연결들의 근거 구성에서 **파생**된다 — 총평으로 부여하지 않는다.
```

#### 6.3.2 연결의 근거 등급

| 등급 | 근거 유형 | 전례 필요? |
|---|---|---|
| **S1** | **구조적·제도적 필연** — 계약 조항, 물리 용량, 규제 요건상 그렇게 될 수밖에 없음 | **불필요** |
| **S2** | 통계적 관계 — 데이터에서 반복 관측된 반응·탄력성 | 필요 |
| **S3** | 사례적 선례 — 과거 유사 국면에서 관측된 전개 (n 적음) | 필요 |
| **S4** | 행위자 유인 — 표명된 이해관계·공개 전략·제약에 비추어 합리적 | 부분적 |
| **A** | **가정** — 근거를 제시하지 못함. LLM이 매끄럽게 이었을 뿐 | — |

**S1이 유기성의 핵심 통로다.** 전례가 없어도 물리·계약·규제상 필연인 연결은 그대로
통과한다. 전례 없는 구조 변화가 배제되지 않는 이유가 여기 있다.

#### 6.3.3 세 가지 규칙 — 날카로움은 여기서 나온다

**① 연결 삽입은 무료가 아니다.**
AI가 사슬을 성립시키기 위해 중간조건을 추가하면, 그 삽입 자체가 **새로운 연결**이며
자기 근거를 요구받는다. 이 규칙이 없으면 어떤 조합이든 중간항 추가로 이어붙일 수 있다 —
바로 §6.4가 경고하는 실패 그 자체다. **삽입 행위는 반드시 기록된다.**

**② 가정(A)은 금지가 아니라 표시다.**
근거 없는 연결을 즉시 기각하면 새로움까지 함께 죽는다. 대신 **A로 명시하고 그대로 둔다.**
그러면 Scenario는 "몇 개의 미검증 가정 위에 서 있는가"로 자동 채점된다.

**③ 직렬 가정은 급격히 약해진다.**
A 연결이 사슬에 직렬로 놓이면 불확실성이 곱해진다. 가정 4개로 이어붙인 경로는
**논쟁 없이, 계산으로** 약한 Scenario가 된다. 여기가 "이어질 수 없는 확률적 서사"가
죽는 지점이다 — 사람의 판단이 아니라 구조가 죽인다.

> **거르는 기준은 "새로움"이 아니라 "근거 없음"이다.**
> 참신하지만 각 연결이 지지되는 경로는 자유롭게 통과한다. 익숙하지만 가정으로
> 이어붙인 경로는 약하게 평가된다. **전례 없는 조합 + 전례 있는 메커니즘**이
> 새 Scenario의 정상적인 형태다.

#### 6.3.4 Scenario 수준의 판정

연결 심사 결과에서 파생된다. 총평 4기준(근거성·정합성·개연성·중요성)은 유지하되,
앞의 셋은 연결 등급 구성에서 계산되고 **중요성만 Domain 판단**이다.

```
연결 대부분 S1~S3 + 중요        → 핵심 Scenario (Signpost·Outlook 산출)
가정 소수 + 영향 매우 큼         → Tail-risk / Wildcard (별도 트랙, 축소 산출)
직렬 가정 다수 / 핵심 연결이 A   → 제외 또는 "근거 확보 시 재심" 보류
정합성 위반(전제 상호 모순)      → 즉시 제외 (등급과 무관)
```

정합성 위반만 등급과 무관하게 즉시 탈락한다 — 서로 모순되는 전제는 근거 문제가 아니라
논리 문제이기 때문이다.

### 6.4 AI의 서사는 증거가 아니다 **[원칙]** — 최우선 Pitfall

> **AI가 설명할 수 있다는 것은 Scenario가 성립한다는 증거가 아니다.**

어떤 극단적 사건 조합에도 LLM은 중간조건을 추가해 문법적으로 매끄러운 인과서사를
만들 수 있다. **설명할 수 있다는 것과 실제 발생할 만하다는 것은 전혀 다르다.**
AI의 서사 생성 능력을 근거로 인정하면, 이 시스템은 분석체계가 아니라 **데이터를 소재로
한 소설 생성기**가 된다.

이 실패를 막는 것은 선언이 아니라 §6.3의 구조다:

- 매끄러움은 연결 등급을 올리지 못한다. **문장의 설득력과 근거는 다른 축이다**
- 중간항 추가가 기록되므로, 서사를 성립시키기 위한 삽입이 **보이게** 된다
- §2.2 ③층의 양방향 검사(E5)는 **설명의 정합성**만 검증한다. 근거성·개연성은
  §6.3과 E7·E8이 담당한다
- 모든 연결에 **지지 근거와 반대 근거를 함께** 기록한다 (`scen_evidence`).
  지지만 모으면 확증편향의 자동화다

### 6.5 "채택"과 "생성"의 관계 — 배치되지 않는 이유 **[원칙]**

§6.3의 채택 절차가 유기적으로 작동하면, 그것도 결국 생성 아닌가? — **맞다. 채택은
생성적이다.** 이를 부인하지 않는다. 차이는 생성 여부가 아니라 **무엇이 생성을
제약하는가**에 있다.

| | 제약 | 결과 |
|---|---|---|
| AI 서사 생성 | **서사적 매끄러움** — 말이 되면 통과 | 무엇이든 만들어진다 |
| 검증 채택 | **연결별 근거** — 근거가 있어야 통과, 없으면 표시되고 약해짐 | 근거 있는 조합만 강하게 존재한다 |

즉 §6.4가 거부하는 것은 *생성 행위*가 아니라 **매끄러움을 근거로 착각하는 것**이다.
근거를 제약으로 삼는 생성은 §6.4와 충돌하지 않는다 — 오히려 그것이 §6.4가 요구하는
바다.

#### 유기성의 소재지

헌장 §5.1(유동적·유기적)이 개념 분리 후 어디에 살아 있는지를 명시한다.
이것이 흐려지면 분리가 곧 경직화가 된다.

| 층 | 유기성 |
|---|---|
| Market State | 완전 데이터 주도 |
| **Regime** | **완전 데이터 주도. 발견·생성·소멸 전부 데이터** — 유기성의 본진 |
| Transition | 데이터 주도 |
| **Scenario** | 후보 생성은 기계적·조합적, 채택은 **연결별 근거 심사**. 사람은 심사자 |
| Conditional Outlook | 데이터 주도 |

Scenario 층의 유기성은 **세 개의 보호 통로**로 유지된다:

1. **S1 등급** — 전례 없어도 구조적·제도적 필연이면 통과 (§6.3.2)
2. **Regime 신규 모드 탐지** — 데이터가 전례 없는 구조를 발견하면, 그 발견 자체가
   새 연결의 S2 근거가 된다 (§2.3)
3. **Wildcard 트랙** — 근거는 약하나 영향이 큰 경로를 제외하지 않고 별도 보존

그리고: 살아있는 Scenario 수에 인위적 상한을 두지 않는다. Signpost도 고정 목록이
아니라 기여도 기준으로 부상·퇴장한다(§8).

## 7. 확률 — 대상별 분리 **[원칙]**

### 7.1 네 종류를 섞지 않는다

"현재 공급긴축 Regime일 확률 70%"와 "향후 12개월 내 공급위기 Scenario 현실화 가능성
70%"는 **완전히 다른 주장**이다. 하나의 `probability` 컬럼에 넣을 수 없다.

| 확률 | 의미 | 산출 주체 |
|---|---|---|
| `regime_membership_probability` | 현재 어느 Regime에 속해 있을 확률 | 필터링 (데이터) |
| `transition_probability` + `horizon` | 시계 내 Regime 전환 확률. **시계 없이는 무의미** | 추정 (데이터) |
| `scenario_likelihood` | Scenario가 현실화될 가능성 | 조건 충족도 + Domain 판단 |
| `conditional_outlook` = P(Y \| Scenario) | Scenario 전제 하의 결과 분포 | 조건부 추정 |

### 7.2 동적 갱신 경로 **[원칙]** — 채택은 느리게, 갱신은 빠르게

Scenario가 검증 게이트를 거친 구성물이라면, 그 가능성은 매일 어떻게 움직이는가?
추진안의 핵심 요구(*"시장정보 변화 → Signpost 감지 → 시나리오 확률 및 가격전망
재산정"*)를 만족시키려면 이 연결부가 반드시 있어야 한다.

```
채택 / 수정 / 퇴장   ← 검증 게이트 (주·월 단위, Domain 개입)
확률 갱신            ← Signpost 충족도 + Regime 소속확률 + Transition 확률 (일별, 자동)
```

**핵심 장치: Scenario의 전제를 관측 가능한 조건으로 분해해 둔다.** 채택 시점에
"이 Scenario가 성립하려면 무엇이 참이어야 하는가"를 Signpost로 명시해두면, 그
조건들의 충족도가 매일 갱신되면서 `scenario_likelihood`가 자동으로 움직인다.
게이트를 매일 돌리지 않아도 확률은 매일 살아 있다.

### 7.3 숫자를 강제하지 않는다 **[원칙]**

Scenario 확률은 정밀한 통계확률로 제시하기 어려운 경우가 많다. 근거가 제한적이면
억지로 숫자를 만들기보다 다음을 허용한다:

```
정량확률  ·  확률구간  ·  상대적 가능성 등급  ·  Domain override  ·  unscored
```

**모든 Scenario에 숫자를 붙이는 것이 객관적인 것은 아니다.** 확률과 함께
**근거 수준(confidence)** 을 표현하는 것이 더 중요하다.

## 8. Signpost와 Trigger

### 8.1 정의 **[원칙]**

> **Signpost = 특정 Scenario의 전제가 충족되거나 그 전개경로가 현실화되고 있음을
> 선행 또는 동시적으로 보여주는 관측 가능한 신호.**

v1.0은 "구조 변화를 선행 예고하는 변수"로 한정했으나, 개념 분리 후에는 범위가 넓어진다.
Signpost가 나타낼 수 있는 것:

- 현재 Regime의 강화 또는 약화
- 특정 Scenario의 전제 충족
- Scenario 경로상 특정 단계로의 진입
- 핵심 사건의 발생 가능성 변화
- Scenario 현실화 가능성의 상승·하락
- 의사결정 Trigger와의 거리

**Regime Transition Indicator는 Signpost의 한 유형으로 포함된다.**

### 8.2 정량화 **[가설]**

추진안이 요구한 정량화가 이 틀에서 정의된다:

| 요구 | 정의 |
|---|---|
| 예측력 | 해당 변수가 상태·Regime·Scenario 가능성 갱신에 기여하는 정보량 |
| 선행시차 | 변수 변화와 상태·확률 변화 사이의 lag |
| Trigger 임계 | §8.3의 조건식 충족 |

- Signpost는 고정 목록이 아니라 기여도 기준으로 **부상·퇴장**한다 (추진안 Discussion의
  표들은 초기 후보이자 검증 대상이다)
- 다차원이므로 "어느 차원을 움직이는가"까지 산출된다
- 재추정마다 Signpost가 뒤바뀌면 신뢰할 수 없다 → E10

### 8.3 Trigger는 단일 cutoff가 아니라 조건식 **[원칙]**

v1.0의 "모드 경계 교차에 대응하는 관측변수 수준"은 지나치게 단일 변수 중심이었다.
실제 Trigger는 다음 형태를 포함한다:

```
단일 변수의 절대수준  ·  변화속도  ·  일정 기간 이상의 지속
여러 지표의 동시 정렬  ·  조건부 조합  ·  Domain상 의미 있는 사건의 발생
```

**조합·정렬이 일급 개념이다** — 단독으로 약한 신호 여럿이 같은 방향으로 정렬할 때가
진짜 신호다 (추진안: *"여러 Factor가 동시에 같은 방향으로 변화하면"*).

Trigger는 **Scenario 또는 의사결정 상태를 변경시키는 조건식**으로 정의한다.

---

## 9. Conditional Outlook **[원칙]**

채택된 Scenario별로 가격·Basis·Spread·Netback·변동성의 **조건부 분포**를 산출하고,
`scenario_likelihood`로 가중한 **전체 혼합분포**를 함께 낸다.

- 핵심 산출은 절대가격 수준이 아니라 **예상범위(분포)와 상대가치**다
- 기준선은 이후 판단의 출발점인 입력값이지 최종 산출이 아니다
- Tail-risk / Wildcard Scenario는 혼합분포에 포함시킬지 여부와 가중을 별도 규칙으로
  관리한다 (근거가 약한 경로가 전체 분포를 지배하지 않도록)

## 10. 실증 항목

엔진 구축에 앞서 이 문서의 가설·설계 선택을 데이터로 확인한다.
E1~E6은 기술 검증, **E7~E11은 이 프로젝트의 핵심 위험**을 다룬다.

| # | 실험 | 확인하는 것 |
|---|---|---|
| E1 | 변수군별 선행시차·증분 설명력 | H1 (§4.2). Target·시계별로 측정 |
| E2 | 스케일 분해의 안정성 | s_구조가 느리게·해석 가능하게 움직이는가 (§3.3) |
| E3 | Regime 탐지의 재현성 | 재추정 시 Regime이 뒤바뀌지 않는가 (§2.3) |
| E4 | 분포·꼬리 지향 학습의 효과 | 점추정 지향 대비 무엇이 달라지는가 (§4.3) |
| E5 | 서사 양방향 검사 | ③층 해석이 상태와 정합하는가 (§2.2). **정합성만** |
| E6 | 임베딩의 방향 민감도 | 같은 토픽·반대 함의를 구별하는가. 판정에 따라 좌표계 대응 분기 |
| **E7** | **연결 등급의 신뢰성** | ① 근거 없는 연결(A)을 A로 표시하는가, 아니면 그럴듯한 근거를 지어내 S등급을 부여하는가 ② **중간항 삽입을 기록하는가** — 사슬을 성립시키려 추가한 연결이 보이는가 (§6.3.3) |
| **E8** | **Counter-evidence 회수** | 지지 근거뿐 아니라 **반증을 함께** 가져오는가. 지지만 모으면 확증편향의 자동화 (§6.4) |
| **E9** | **Regime–Scenario 분리** | 현재 상태 설명과 미래 경로 예측을 구분해 산출하는가 |
| **E10** | **Signpost 안정성** | 재추정마다 과도하게 바뀌지 않는가 (§8.2) |
| **E11** | **Decision-usefulness** | 과거 실제 판단에서 산출물이 판단기준·진입시점에 유의미한 정보를 주었는가 |

> **E11 가드레일.** 이 실험은 헌장 §1.1(과거 의사결정 평가 프로젝트가 아니다)과
> §7.3(백테스트는 회귀 테스트, 단일 사례 성공은 검증이 아니다)의 적용을 받는다.
> 여러 실험 중 하나이며, 이것의 성공이 프로젝트의 목적이 되지 않는다. 복수 사례로
> 구성하고 결과 판정 기준을 사전 동결한다 (헌장 §7.4).
